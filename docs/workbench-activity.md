# 会话／任务状态与提醒（P0-B）

第二阶段为项目工作流增加“会话与任务”入口。会话与提醒已合入右侧任务栏，与任务方块、归档共用一个侧栏；任务通知继续使用短时浮层，不占用终端的常驻高度。它展示可核实的运行信息，不从终端文字、进程存活或连接断开推断模型任务完成。

## 使用方式

- 从侧栏细柄展开任务区；四个页签为“任务／归档／会话／提醒”。“提醒”查看完整工作动态，“会话”查看会话详情。侧栏标题、提醒页签和收起细柄保留未读提示；右上角只保留系统窗口操作。没有提醒时不显示常驻状态横带。
- 按实际工作目录筛选项目；主目录与 worktree 分开。项目列表的现场操作旁也有会话入口，复用现场检查取得的实际目录，不重新配置项目。
- 普通本地终端提供“定位终端”；已收纳且仍连接的非归档终端定位到原实例小窗，其余终端定位到主区，保留归档分类且不自动重连；原生 Harness 会话提供“打开工作台”。工作台通过已有官方页面的导航协议打开指定会话，只有官方页面确认目标会话后才报告定位成功。导航失败或超时会保留说明，不重新提交任务。
- 完成、失败、待审批事件在右上角弹出通知，同时进入应用内提醒记录。完成与失败在 8 秒后收起，鼠标悬停或键盘焦点进入时暂停计时；审批提醒持续保留，直到处理、手动关闭或可靠状态失效。最多同时显示三条，审批优先；其余仍可在侧栏提醒中查看。侧栏展开时暂停浮动提醒，收起后继续显示。
- 通知保留目录、会话和任务归属，点击会筛选项目并定位对应条目。自动弹出不移动当前输入焦点；关闭卡片标记已读，超时仅收起卡片，二者均保留历史。可以在侧栏标记全部已读、静音当前项目或清空提醒。通知和项目入口都定位到同一个侧栏；状态说明在底部默认折叠。静音不隐藏会话详情的待审批状态，也不回答审批。
- 会话列表每条约 44px，点击名称定位；状态只用左侧图标角上的灯表达，灯旁不加文字。来源、完整目录、身份与状态依据从悬停提示或行尾箭头查看；回合结束保持“本轮结束”语义。
- 审批通过“查看请求”展开，展示后端工具名、原因、实际操作以及后端提供的选项。仅在身份、会话、任务、审批及选项重新核对通过后发送用户选择；完整操作无法核对时禁用“仅允许一次”，仍可明确拒绝、取消或打开官方工作台查看。

小窗口网页或终端的实际内容区使用 16:10，36px 标题栏与网页额外的 32px 地址栏不占内容比例。上下停靠时分别计算网页与终端所需高度，空间不足时只显示保活方块，调高后复用原实例。扩大阅读或输入空间继续使用“放大到主工作区”，不增加独立全屏模式。

## 状态灯

Tasks 方块、小窗标题与 Sessions 使用同一 9px 圆形状态灯，随官方事件与快照自动更新。灯色收为蓝、绿、琥珀、红、灰五组：蓝色空心/实心分别表示待运行/执行中，绿色空心表示等待输入或本轮结束、实心表示目标完成；琥珀实心表示需要确认、空心表示中断；红色实心/空心分别表示任务异常/连接异常；灰色虚线圈表示断开、普通空心圈表示未知。具体任务阶段、归档分类与实例存活仍由悬停提示和可访问名称完整表达，不合并底层状态。图例默认折叠，可从显示设置或底部“状态说明”展开查看。

侧栏内部统一使用白色内容面、浅灰 1px 边界、8px 圆角和 12px 外距。任务方块随栏宽排列为最多五列，默认仅显示类型图标、两行名称与灯，不重复显示类型文字；打开小窗口后，竖向侧栏顶部改为一排可横向滚动的 104px 保活方块。会话默认 48px 单行卡片、8px 间隔；提醒默认两行，完整目录与会话身份保留在悬停提示。会话与提醒共用紧凑项目筛选及图标工具栏，连接说明与灯图例统一收进底部折叠区。页签仅在数量大于零时显示计数。

已接收尚无执行证据时显示“待运行”；终端连接正常但没有新鲜 CLI 任务事件时任务阶段仍未知，空心绿灯只表示实例存活；过期或失活的旧审批不会继续亮黄灯。断开与连接错误分别标注，均不表示任务完成。回合结束和任务完成保留独立状态。

## 状态与来源

| 来源 | 进程状态 | 任务状态 | 连接状态 |
| --- | --- | --- | --- |
| 普通本地终端、DeepSeek TUI、自定义 CLI | 来自终端连接事件的终端进程存活／退出信息；不等同于 CLI 子进程或模型任务状态 | 未接入任务适配器，显示未知 | 终端连接状态 |
| LyShell 启动的 Codex／Claude TUI | 同上，独立于回合状态 | 官方 hooks 的开始、回复结束、审批；Codex 另有中断、Claude 另有异常停止 | 独立通知通道；不依赖原生 Harness 后台 |
| Harness 内置聊天中手动输入的回合 | 由官方后台托管 | 官方 live `session/event` 的开始、结束、异常、中断和审批审计事件；结束显示“本轮结束” | 只读现有后台，每轮快照读取；不启动或接管会话 |
| 原生 Harness work API 创建的会话 | 后台托管；不伪造独立终端进程证据 | 来自官方回合与原生工作接口的 accepted、running、completed、failed、cancelled、unconfirmed | 原生桥读取成功、离线或过期 |

原生 work API 的控制范围仍限于当前主进程已观察到的凭据及其会话。内置聊天新增独立的只读回合观察，不授予 native work 控制权；work API/Pet 当前自动任务期间不重复观察，同一会话在自动任务结束后的手动续聊可以提醒。Codex／Claude 的 TUI 接入、版本与信任要求见 [TUI 通知接入](tui-activity.md)。内置聊天和 TUI 的“本轮结束”都不验证整个目标完成；审批分别引导到原工作台或原终端处理。

### 内置聊天提醒

- 更新后的 LyShell 与新启动的 Harness 后台会自动加载只读观察器，无需修改官方 profile 或开启额外权限。已运行的旧后台需要正常关闭并重新打开后才能加载新桥；不会为更新功能自动重启共享后台。
- 官方 `turn/start` 建立当前回合，匹配同一 turn 的 `turn/end` 才通知结束／异常／中断。只读取运行期事件，不扫描历史正文；初次快照和后台换代不重播历史终态，之后两次轮询间快速结束的新会话仍能通过有界事件日志提醒。
- 待审批来自官方 `approval/asked`，决定、拒绝或取消后的 `approval/decided` 撤销待办；并行审批按实际 ID 分别记录。观察器不注册 `approval/request` 处理器，不代答、不改变官方审批链。点击通知可在会话列表打开对应工作台。
- 快照只包含后台身份、会话／回合／事件 ID、状态、时间和官方 `session.header.cwd`，不转发提示词、模型回复或工具参数；缺少目录时显示“目录未提供”，不猜测项目归属。子代理会话不单独弹窗。
- 桥端保留最多 128 个会话的最近回合及 100 条事件，不跨重启保存。读取失败或状态过期即撤销当前审批依据，不推测完成。当前通过已安装官方 dsh `0.2.1-rc.2` 的真实 SessionStore/ApprovalService 验证了事件形状；旧版缺少审批审计事件时不能提供这类审批提醒。
- 自动任务的事件会立即撤销该会话的旧手动回合证据，即使任务在两次轮询之间完整结束，也不会遗留旧审批或遮住原生状态。采集传输上限为 16MiB，容纳上述有界会话、目录、审批 ID 和事件的 JSON 转义；字段数量与长度仍逐项校验。

每次状态快照包含读取时间，条目另记录最后状态变更时间。Renderer 每次读取结束后约 4 秒再次读取；快照超过 12 秒、连接异常或条目标为过期时，不再作为当前状态或审批依据。读操作不启动后台、不取得执行租约、不重发任务。

## 身份与故障规则

- 会话／任务身份由后台 `instanceId + instanceEpoch + sessionId + taskId` 组成；审批再关联实际审批 ID。凭据、owner 与桥 key 只留在主进程，不进入 Renderer、提醒或持久化。
- 主进程汇总当前后台各个已观察凭据，保留各会话最后一次已确认任务。切换原生会话不把前一会话的终态移到新会话。
- 断线、超时、畸形响应和旧后台回执不表示完成。未终结任务降为未知，已确认终态保留为过期历史；审批路由清空。后台换代会作废旧会话及审批归属。
- 并发读取的迟到响应不覆盖期间落地的新回执；同任务终态不回退为 running；官方任务创建时间用于拒绝旧任务覆盖较新任务。
- 审批发送前重新读取同一凭据状态并校验后台、会话、任务、审批与官方选项。实际操作必须来自同任务／会话／callId 的完整 tool-call；截断输出、序号缺口和不完整参数不允许据此批准。
- 请求超时不自动重试批准、提交或取消。工作台导航也只读取同一次请求的回执，不重复下发导航或任务。

任务／会话／提醒为运行期数据，不跨应用重启恢复控制权。只持久化项目静音偏好，不保存任务内容、审批、后台凭据或运行状态。每个首次接入会话的历史完成／失败任务都不会当作新事件提醒，首次待审批仍可提醒。同后台同会话同任务同事件去重；提醒最多保留最近 100 条。轮询只报告实际观察到的事件，不承诺重建两次读取之间从未观察到的中间事件。本版为应用内提醒，未接入系统通知或声音。

## 实现与验证入口

- 共享类型：`src/shared/workbench-activity.ts`、`src/shared/activity-navigation.ts`。
- 主进程：`src/main/dsh/activity.ts`、`web-activity.ts`、`activity-navigation.ts`；原生工作回执在 `work.ts` 登记，内置聊天观察器在 `resources/dsh-bridge/index.mjs`。
- IPC：`workbench-activity:request` 与 `workbench-activity:navigate`，同步覆盖 handler、validator、preload 及 Renderer 消费端。仅应用窗口主 frame 可访问；外部 work API 的凭据隔离保持原有约定。
- 界面：`TaskShelf.tsx`、内嵌内容 `WorkbenchActivity.tsx`、`ActivityNotifications.tsx`；`WorkbenchActivityMonitor` 单独负责轮询、提醒与旧入口路由；`stores/activity-toast.ts` 负责提醒去重与优先级，项目入口复用 `ProjectSceneProjectActions`。

开发验收脚本、日志、实际 Electron 截图及机器可读结果位于本 checkout 的 `tmp/workbench-activity/`，不随发布打包。主进程采集模块由原生 Harness 助手实现；代码审查、IPC 和界面集成、图形检查与最终验证由 Codex 完成。验收结果见计划中的第二阶段记录。
