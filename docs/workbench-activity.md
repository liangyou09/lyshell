# 会话／任务状态与提醒（P0-B）

第二阶段为项目工作流增加“会话与任务”入口。当前入口位于右上角标题栏铃铛；任务通知采用 macOS 风格浮层，不占用终端的常驻高度。它展示可核实的运行信息，不从终端文字、进程存活或连接断开推断模型任务完成。

## 使用方式

- 点击右上角铃铛打开通知中心；“提醒”查看工作动态，“会话”查看会话列表。铃铛角标为未读数，即使浮层已自动收起也保留。没有提醒时不显示常驻状态横带。
- 按实际工作目录筛选项目；主目录与 worktree 分开。项目列表的现场操作旁也有会话入口，复用现场检查取得的实际目录，不重新配置项目。
- 普通本地终端提供“定位终端”；原生 Harness 会话提供“打开工作台”。工作台通过已有官方页面的导航协议打开指定会话，只有官方页面确认目标会话后才报告定位成功。导航失败或超时会保留说明，不重新提交任务。
- 完成、失败、待审批事件在右上角弹出通知，同时进入应用内提醒记录。完成与失败在 8 秒后收起，鼠标悬停或键盘焦点进入时暂停计时；审批提醒持续保留，直到处理、手动关闭或可靠状态失效。最多同时显示三条，审批优先；其余仍可在历史中查看。
- 通知保留目录、会话和任务归属，点击会筛选项目并定位对应条目。自动弹出不移动当前输入焦点；关闭卡片标记已读，超时仅收起卡片，二者均保留历史。可以在通知中心标记全部已读、静音当前项目或清空提醒。静音不隐藏会话详情的待审批状态，也不回答审批。
- 审批展示后端工具名、原因、实际操作以及后端提供的选项。仅在身份、会话、任务、审批及选项重新核对通过后发送用户选择；完整操作无法核对时禁用“仅允许一次”，仍可明确拒绝、取消或打开官方工作台查看。

## 三种状态与来源

| 来源 | 进程状态 | 任务状态 | 连接状态 |
| --- | --- | --- | --- |
| 普通本地终端、Codex／Claude／DeepSeek TUI、自定义 CLI | 来自终端连接事件的终端进程存活／退出信息；不等同于 CLI 子进程或模型任务状态 | 未接入可靠任务适配器，明确显示未知 | 终端连接状态 |
| 原生 Harness work API 创建的会话 | 后台托管；不伪造独立终端进程证据 | 来自官方回合与原生工作接口的 accepted、running、completed、failed、cancelled、unconfirmed | 原生桥读取成功、离线或过期 |

原生范围限于当前 LyShell 主进程已观察到的原生 work API 凭据及其会话。官方 Web 自行创建的会话、PetLink 会话、其他 CLI 对话不因此获得任务适配能力。没有可靠等待输入事件的 CLI 不会被标记为等待输入；本版可靠等待事件为原生审批。

每次状态快照包含读取时间，条目另记录最后状态变更时间。Renderer 每次读取结束后约 4 秒再次读取；快照超过 12 秒、连接异常或条目标为过期时，不再作为当前状态或审批依据。读操作不启动后台、不取得执行租约、不重发任务。

## 身份与故障规则

- 会话／任务身份由后台 `instanceId + instanceEpoch + sessionId + taskId` 组成；审批再关联实际审批 ID。凭据、owner 与桥 key 只留在主进程，不进入 Renderer、提醒或持久化。
- 主进程汇总当前后台各个已观察凭据，保留各会话最后一次已确认任务。切换原生会话不把前一会话的终态移到新会话。
- 断线、超时、畸形响应和旧后台回执不表示完成。未终结任务降为未知，已确认终态保留为过期历史；审批路由清空。后台换代会作废旧会话及审批归属。
- 并发读取的迟到响应不覆盖期间落地的新回执；同任务终态不回退为 running；官方任务创建时间用于拒绝旧任务覆盖较新任务。
- 审批发送前重新读取同一凭据状态并校验后台、会话、任务、审批与官方选项。实际操作必须来自同任务／会话／callId 的完整 tool-call；截断输出、序号缺口和不完整参数不允许据此批准。
- 请求超时不自动重试批准、提交或取消。工作台导航也只读取同一次请求的回执，不重复下发导航或任务。

任务／会话／提醒为运行期数据，不跨应用重启恢复控制权。只持久化项目静音偏好，不保存任务内容、审批、后台凭据或运行状态。每个首次接入会话的历史完成／失败任务都不会当作新事件提醒，首次待审批仍可提醒。同后台同会话同任务同事件去重；提醒最多保留最近 100 条。轮询只报告实际观察到的事件，不承诺重建两次读取之间从未观察到的中间事件。本版为应用内提醒，未接入系统通知或声音。

## 实现与验证入口

- 共享类型：`src/shared/workbench-activity.ts`、`src/shared/activity-navigation.ts`。
- 主进程：`src/main/dsh/activity.ts`、`activity-navigation.ts`；原生工作回执在 `work.ts` 登记。
- IPC：`workbench-activity:request` 与 `workbench-activity:navigate`，同步覆盖 handler、validator、preload 及 Renderer 消费端。仅应用窗口主 frame 可访问；外部 work API 的凭据隔离保持原有约定。
- 界面：`WorkbenchActivity.tsx`、`ActivityNotifications.tsx`、标题栏的 `WorkbenchActivityButton.tsx`；`stores/activity-toast.ts` 负责提醒去重与优先级，项目入口复用 `ProjectSceneProjectActions`。

开发验收脚本、日志、实际 Electron 截图及机器可读结果位于本 checkout 的 `tmp/workbench-activity/`，不随发布打包。主进程采集模块由原生 Harness 助手实现；代码审查、IPC 和界面集成、图形检查与最终验证由 Codex 完成。验收结果见计划中的第二阶段记录。

右上角通知改版的独立预览与验证记录在 `tmp/workbench-notifications/`。该改版保留原有状态来源和审批边界；没有新增系统通知、声音或跨重启任务历史。
