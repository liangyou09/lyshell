# 插件资源回收约束

禁用和卸载通过 `releasePluginSessions` 进入统一的资源生命周期。资源登记、执行权限和清理回执分别处理，避免关闭尚未完成时丢失索引。

## 生命周期

1. 撤销 token、递增资源代次，旧请求立即失效。
2. 同步登记需要清理的会话，保留其插件归属，再发布页面和终端失效通知。
3. 删除插件自有保存项。借用用户或其他插件的配置只回收运行时。
4. 每个会话只启动一次原生关闭；并发回收等待同一任务。新一轮回收同时纳入旧的在途任务与新登记的资源。
5. 原生关闭成功后解除运行时归属。失败时保留归属与删除意图，下一轮重试；所有等待者收到失败。
6. 卸载只有在会话回收及宿主进程清理都成功、插件记录和代次仍一致时，才移除记录和安装目录。

归属保留用于防止漏清理及跨插件抢占，不恢复 token 或旧代次的执行权限。通知或保存项删除失败不会中止其他资源的关闭；错误在全部任务落定后统一返回。保存项删除失败时仍保留保存项归属，供下次补完。

## 回归验证

| 交叉场景 | 必须保持的行为 | 用例位置 |
| --- | --- | --- |
| 借用用户或其他插件配置，并发禁用 | 保存项不删除，所有调用等待同一次关闭 | `resource-registry.test.ts` |
| 并发关闭失败，再次回收 | 失败归属保留，重试只启动一次关闭 | `resource-registry.test.ts`、`session-manager.deletion.test.ts` |
| 重新启用后产生新资源，再次禁用 | 新资源关闭，旧任务也必须等待 | `resource-registry.test.ts` |
| 同步通知重入及通知抛错 | 先登记、后通知，不遗留悬空任务 | `resource-registry.test.ts` |
| 宿主重启先失败，立即重试卸载 | 保留插件记录，等待仍在关闭的借用终端 | `plugin-uninstall.cleanup.test.ts` |
| 卸载期间重新安装、启用或回收 | 旧卸载不得删除新状态 | `plugin-uninstall.cleanup.test.ts` |
| 串口打开与删除重叠、连接与断开重叠 | 迟到连接不能复活资源或覆盖旧句柄 | `session-manager.deletion.test.ts` |
| SSH 克隆创建与禁用重叠，迟到 channel 关闭失败 | 回收等待创建落定，关闭失败保留运行时和归属以供重试 | `session-manager.plugin-resources.test.ts` |
| SSH shell 永不响应，超时后回调迟到 | 每次回收最多等待创建 5 秒，超时保留归属，迟到回调仍关闭 channel | `session-manager.plugin-resources.test.ts` |
| MCP 显式重连、授权期间禁用或更换会话 | 新连接登记运行时归属，旧代次不得重连，用户保存项保留 | `reconnect-resources.test.ts` |
| Python oneshot 超时与禁用重叠 | 根进程存活时开始树清理，执行结果等待清理回执并传播失败 | `engine.cancellation.test.ts`、`host-mgr.restart.test.ts` |

## 原生关闭限制

内置串口绑定会在原生关闭前清空 fd。若关闭随后报错，`isOpen=false` 不能证明句柄已释放，也不能靠再次调用关闭恢复 fd。此时保留失败状态，并在重试时提示重启应用；不能返回回收成功。
