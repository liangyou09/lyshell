# LyShell 小窗口内存优化完整实施方案

版本 1.0    日期 2026年10月28日    状态 待实施

本方案面向 LyShell 开发与验收人员，定义任务归档和激活、侧栏交互、真实实例复用、网页休眠恢复、贴图预算及 Rust 冷历史试点的实施规则。先完成可测量的 TypeScript 与 Electron 生命周期优化，再依据冷数据来源和总成本决定是否引入 Rust。目标是减少无展示需求的资源占用，同时保持后台任务、终端输入输出和已有任务续接行为正确。

本文交付范围为实施设计。功能修改、安装工具链或依赖、迁移存量数据和操作用户运行环境，仍按原有授权范围执行。本文出现的新增模块、字段、接口和阈值均为设计，不代表已经存在或已经上线。技术能力以项目锁定的 Electron、Node、Chromium 与 xterm 版本为准。

阅读导航：第 1 至 4 章确定目标、基线与所有权；第 5 至 9 章定义任务和网页行为；第 10 章限定 Rust；第 11 至 17 章提供参数、文件范围、阶段、测试和回退。附录 A 为流程伪代码，附录 B 为官方依据。可使用文档标题导航定位各章。

## 1. 目标与首版决策


### 1.1 交付目标

- 新进程启动时，启动快照中的保存任务进入 Archive；未保存任务及本次新建任务不受此规则影响。
- 单个和全部激活只改变任务分类；真实资源由独立需求按预算恢复，不重新执行 shell 命令或 Agent 任务。
- 侧栏点击后保持展开，满足鼠标移出和交互保护条件后约 350ms 收起；固定模式保持展开。
- 所有任务保持可访问的卡片与真实状态，静态展示、离屏和缓存淘汰均不删除任务。
- 普通网页只在可核实的安全范围内深睡；恢复失败保留可理解的状态与明确入口。
- 以应用相关进程总私有内存、峰值及交互延迟验证结果；Rust 是否采用由公平对照决定。

下表将已确认交互与本方案推荐的首版取舍分开。实验参数必须在 P0 后记录最终配置及理由，不将其描述为性能保证。

### 1.3 范围边界

保留 Electron、React、xterm 和现有连接层。终端、PTY、SSH、串口、Agent 执行与审批链不迁移；插件和 Harness 资源继续由原所有者管理。没有对任意网页完整运行现场、sessionStorage、表单、WebSocket 或远端任务复活的通用恢复承诺。现有 SSH 续接范围保持不变，不扩大到 Telnet 上下文恢复。

分类、显示、资源和任务执行分别建模。分类成功不意味着网页加载成功，网页深睡也不意味着任务执行结束。用户主动关闭任务与自动释放普通网页实体必须使用不同命令。

## 2. 必须始终成立的规则


- 同一个资源在同一代最多有一个被协调器认可的真实 guest 或终端展示实体；先确认旧实例销毁，才允许创建替代实例。
- 任一主区真实展示需求存在时，侧栏状态变化不能暂停、搬走或调整该实例尺寸。
- 归档、切栏、收起、离屏、截图失败和编码故障均不能停止 PTY 或重新执行任务。
- 分类操作只修改规定字段；旧启动结果、旧批次和重试不能覆盖更新的用户操作。
- 卡片数量取决于任务记录；缓存、实例与虚拟列表只影响挂载和画面，不影响任务可访问性。
- 休眠只在用户策略允许、恢复方式合格且保护结论明确为 safe 时发生；unknown 和 blocked 均保活。
- 除显式打开和本次激活产生的恢复需求外，缺图、卡片挂载、滚入视口、宽度与 DPI 变化均不能唤醒休眠或仅有元数据的网页。
- 所有可管理队列同时限制条目数和字节；过期结果不能提交，取消也不能提前假定底层内存已经释放。
- 任何状态更新须校验资源所属范围、实例代际及该操作需要的需求或尺寸版本。
- 现有历史保留上限、UTF-16 码元游标、clear、trim 和截断语义保持不变；压缩不用于扩大保留量。
- 只对明确允许的历史副本进行转移或释放；不能把降低 JS heap 当作应用总内存收益。
- 任一阶段都有独立功能开关、验收结果与关闭路径；回退不自动反转用户已经完成的分类操作。

### 3.2 隔离测量

使用独立用户档案、本地页面和固定日志 fixture，避免真实账号、用户表单及活动任务。固定 OS、CPU、内存、刷新率、DPR、窗口尺寸、应用提交、页面数量、终端数量及各预算。网络状态、热缓存与冷缓存分别记录，不混为一次结果。

场景包含 1、10、30 个网页和终端，20、100 张卡片，普通文本、ANSI 密集、中文、emoji、孤立代理项及高熵日志。选取有代表性的组合并加入混合高负载场景，不要求无差别执行所有笛卡尔组合。网页 fixture 包含可安全重载页、表单、POST、上传、音视频、导航中、离线及受控未知状态。

按 PID 去重采集主进程、renderer、guest、GPU、utility 及相关子进程；shell 与 Agent 单列并给出应用相关总量。工作集、私有内存、JS heap、external、ArrayBuffer 及原生自统计分别报告，禁止简单相加重叠指标。Worker 的 RSS 属于整个进程，其他 Node 内存字段按线程采集；ArrayBuffer 已包含在 external 中。[S7][source-s7] [S8][source-s8]

采样覆盖预热稳态、采集峰值、30 秒标签、5 分钟候选、恢复、关闭及反复循环。至少 3 轮独立完整运行；延迟统计每个主要场景建议积累至少 100 次操作，并报告样本数、p50、p95 和范围。采样周期可从 100ms 开始，先测量采样器开销；用操作埋点补充短暂峰值，不能把轮询峰值称为绝对最大值。

### 3.3 P0 必交结果

- 分进程占用与主要保留对象，明确网页、xterm、输出缓冲、贴图和外部任务分别占多少。
- 自动深睡可放行页面的数量、原因及对应内存占比；受保护和未知页面单列。
- 冷历史候选清单，含数据来源、原上限、同步调用者、可释放副本及预计净收益对象。
- 启动归档、单个激活、全部激活但仅可视恢复的首屏时间与峰值基线。
- 实际版本能力、测试 fixture、最终参数和验收阈值。没有测量证据时，Rust 与通用深睡均不得自动进入生产迁移。

## 4. 状态模型与模块所有权


### 4.1 分离持久状态和运行状态

持久任务记录沿用现有仓库，最小涉及 taskId、资源引用、分类与排序。revision 优先复用现有字段；没有持久版本时，由唯一仓库所有者维护本次运行版本并校验 bootId，不因此新增数据库。新增持久字段需要格式版本、默认值及兼容读取规则。

运行状态包括 selectedView、selectedTaskId、panelMode、panelOpen、uiIntentRevision、presentationOwner、resourceState、restoreStatus、presentationReady、restoreDemand、idleSince、protection、缓存和队列。resourceState 表达实体生命周期，restoreStatus 表达加载结果，presentationReady 表达是否已具备交接画面的条件，三者不能互相推断。运行代际与 Promise 不写入任务文件。历史记录中的运行状态只能作为线索，重启后未经核实显示 unknown 或待检查。

```ts
type ShelfRealtimeView = 'tasks' | 'none';
type ResourceState =
  'metadataOnly' | 'live' | 'suspending' |
  'sleeping' | 'restoring' | 'closed';
type RestoreStatus = 'idle' | 'queued' | 'loading' |
  'ready' | 'failed';
type PresentationOwner = 'main' | 'shelf' | 'none';
type Protection = 'safe' | 'blocked' | 'unknown';

interface ResourceToken {
  scopeId: string;
  resourceId: string;
  instanceGeneration: number;
  navigationGeneration: number;
}
interface RestoreDemand {
  resourceId: string;
  source: 'explicitMain' | 'explicitShelf' | 'bulkVisible';
  demandRevision: number;
  requestId: string;
}
```

任务状态、页面恢复状态和历史查询状态不共用一个 success 或 error。scopeId 表示所属项目或资源范围，分类移动不改变其权限。资源可能被多个入口引用时，关闭规则沿用资源所有者的引用协议，不能以删除一个卡片推导关闭全部共享资源。

### 4.2 建议模块


| 模块 | 唯一职责 | 不负责 |
| --- | --- | --- |
| task-shelf-command-service | 启动归档、分类命令、版本校验及保存结果 | 创建网页或执行任务 |
| task-shelf-render-policy | 从当前状态计算实时和采集资格 | 销毁资源或写仓库 |
| resource-presentation-coordinator | 真实实例的位置、尺寸和输入所有权 | 决定任务运行终态 |
| browser-lifecycle | 网页实例、保护、休眠及恢复操作 | 管理插件私有生命周期 |
| browser-restore-scheduler | 优先级、需求失效与恢复准入 | 直接改变分类 |
| task-shelf-frame-cache | 帧所有权、预算、LRU 和释放 | 为补图创建 guest |
| task-shelf-capture-scheduler | 原生采集许可、去重和过期结果 | 用截图模拟实时网页交互 |
| history-store 与 history-codec-worker | 条件性历史存储与有界编解码 | xterm、PTY 或 Agent 执行 |

模块名为建议，不强制为每个逻辑都创建独立文件；实际落位以现有结构、依赖方向和并行任务边界为准。应用级协调器不能跟随某张卡片的 React 挂载周期被反复重建。

renderer 负责 DOM、卡片几何与输入区域，主进程或既有权威资源所有者统一登记实例及批准创建和关闭。若 webview 由 WebTabLayer 挂载，先取得绑定 resourceId、代际和宿主的 createPermitId，再创建元素；通过 Electron 可核验的 guest 附着事件确认实例身份后登记，不能只接受 renderer 上报一个 webContents ID。重复 permit 不得创建第二个实体。创建超时、宿主 renderer 退出和附着失败都进入协调器收尾；没有确认旧创建已终止前，不发替代许可。具体事件与附着关系在 P0 按当前版本验证。[S1][source-s1] [S2][source-s2]

## 5. 启动归档与激活命令


### 5.1 权威写入与启动屏障

启动协调器在唯一任务仓库所有者处生成 bootId，读取并校验保存区任务，固定启动记录及其顺序。对这批记录应用 Archive 分类，沿用当前保存校验与原子保存能力；持久提交成功后发布 ready 状态和首屏 Archive。期间针对保存区的创建与分类命令进入同一串行队列，renderer 可以展示元数据与初始化状态，但不能以本地列表修改冒充提交成功。

新窗口、renderer 重载、组件重挂和列表重读只订阅已提交结果。启动归档仅针对固定快照，本次创建或随后保存的任务不进入旧批次。若项目支持多个进程同时写同一仓库，先核实已有锁与冲突协议；不能把单进程内存队列当作跨进程互斥。

初始化保存失败时保留原始记录与真实分类，发布明确错误，不伪装全部归档成功。允许只读展示；分类命令返回 INITIALIZATION_BLOCKED 并提供重试。重试继续使用受校验的启动批次；若数据已经发生合法外部变化，重新核对版本并显示冲突，不覆盖新状态。

### 5.2 分类命令

单个激活传一个元素；全部激活传点击时 Archive 记录的稳定快照。校验请求属于当前 bootId、scopeId，任务 ID 唯一，长度合法。数据量较大时由仓库对批次快照登记并返回 batchId，分片传输只拆载荷，不改变点击时集合。

```ts
interface ActivateTasksCommand {
  bootId: string;
  scopeId: string;
  requestId: string;
  items: Array<{
    taskId: string;
    expectedRevision: number;
  }>;
}
// 每项仅有一种分类结果
type ClassificationStatus =
  'moved' | 'alreadyTasks' | 'conflict' |
  'missing' | 'failed';
```

仓库在串行执行区内读取当前状态，校验版本和分类，只更新分类及必要排序字段。既有 Tasks 顺序保持；新增项按快照顺序追加，若仓库已有明确排序规则则沿用并验证。已删除或版本变化的项返回 missing 或 conflict，不用旧快照覆盖。

保存成功后再发布分类结果。如果当前保存接口是整批原子写入，整批写失败必须把全部待变更项报告为 failed；只有实际支持部分提交时才报告部分保存成功。结果数量满足 total = moved + alreadyTasks + conflict + missing + failed。

同 requestId 且同请求摘要返回同一结果；同 ID 不同载荷拒绝。去重表按本次运行限制容量，淘汰后旧请求仍由版本校验和目标状态保证不重复产生副作用。失败重试生成新 requestId，重新读取失败项，只重试仍满足条件的记录，不重新提交整份旧快照。

### 5.3 分类成功后的展示

发起激活时记录 uiIntentRevision。分类提交结果始终同步到记录；切栏、选中、定位和生成恢复需求只在该界面意图仍有效时执行。用户随后切栏、另选任务或显式关闭会使旧界面动作失效，不回滚已成功的分类。异步布局完成后再次核验意图，避免旧回调抢回侧栏或恢复用户已经不看的页面。

单个激活成功后切到 Tasks，选中并滚动定位目标；真实实例存在则经展示协调器复用。实例不存在且当前侧栏为实时模式时，发出 explicitShelf 需求；静态模式保持卡片并提供在主区打开入口。

全部激活成功后切到 Tasks，保持仍有效的当前选择，否则选择首个成功项，不轮流聚焦每个资源。完成布局后，只对本次成功项中当时可视、允许侧栏真实展示的网页生成一次 bulkVisible 需求。其他项保持贴图或占位。后续仅滚动到它们，不自动补发恢复；用户选择卡片或在主区打开时再恢复。这条规则保证滚动和补图不会变成批量预加载。

分类失败与资源恢复失败分别展示，例如 10 项已移至 Tasks 当前 2 项页面恢复失败。分类重试仅调用仓库命令，恢复重试仅调用生命周期入口。任何激活都不新建 shell、不重放启动命令、不重提 Agent、不重放 POST、不自动回答审批。

## 6. 展示权限与侧栏交互


### 6.1 真实实例仲裁

同一资源最多有一个真实展示位置。主区有有效需求时 presentationOwner 为 main；侧栏展示贴图或占位，不改变其视口或 PTY 行列。主区释放后，符合实时条件的侧栏才可以接管。位置转移先撤销旧输入和几何所有权，再交给新位置，保持实例、连接及输入现场。

侧栏实时资格要求 selectedView 等于 tasks 且 realtimeView 等于 tasks，侧栏展开、宿主可见、卡片进入有效可视区、资源允许侧栏展示。计算资格时不要求实例已经创建；是否需要恢复另由需求判断。实际交互还要求实例 ready 且展示所有权归侧栏。主区显示独立于侧栏 realtimeView。

每次选栏、收起、可视区域或策略变化推进 policyRevision 与相应 demandRevision。实例替换推进 instanceGeneration，主文档导航推进 navigationGeneration，几何或 DPR 变化推进 geometryRevision；不同版本不能互相代替。截图提交校验其捕获时的这些版本，防止旧宽度、旧导航或旧租约覆盖新画面。

### 6.2 点击与自动收起

卡片、分类、全部激活、按钮、输入及主区打开的事件只改变各自状态，不调用 closePanel。展开状态不与异步恢复 Promise 的完成绑定。自动模式在指针离开全部有效区域且没有保护条件时启动约 350ms 定时器；返回立即取消，回调再次核对模式、指针、代际和保护状态。

有效区域包括侧栏、通过固定定位展示的真实终端或 webview，以及归属该侧栏的菜单和弹层。采用当前实例的区域注册和可验证的宿主/guest 边界信号，不能仅看 aside.contains。缩放、DPI、多显示器和窗口失焦后的坐标应重新获取。guest 信号只影响相应实例的交互状态，校验来源与代际，不授予资源操作权限。[S2][source-s2]

保留真实编辑焦点、IME、主动键盘导航、拖动、尺寸调整和所属菜单打开的保护。普通按钮残留焦点不视为编辑。终端或网页输入框仍持有编辑焦点时，即使鼠标移出也保持展开；焦点转移后重新核对收起条件。无法可靠区分 guest 中编辑状态时采取保守保护并记录原因，不能仅凭缺少事件认定无输入。

固定模式不自动收起。显式关闭按钮和已有关闭快捷键仍有效，并按既有安全焦点交接规则执行；不得在 IME 组合输入中意外提交或丢失文本。关闭侧栏只撤销侧栏展示与采集需求，不停止任务，不修改固定模式设置。

### 6.3 终端边界

缩略图读取既有缓冲绘制 Canvas，不修改 PTY 行列，不额外建立输出订阅。真实终端尺寸只由当前展示所有者提交给既有 resize 调度；拖动帧同步继续由并行任务负责。离屏可以停止预览与非必要绘制，但仍消费既有终端输出与背压，禁止堆积一条无界的隐藏写队列。

关闭真实终端资源时核验订阅、插件、DOM、注册表和 store 引用的释放；侧栏隐藏与归档不得触发这条关闭路径。xterm 10000 行配置及 MCP 输出容量是否调整属于另一个保留策略决定，首版不以缩短历史换取未说明的收益。

## 7. 网页闲置与深度休眠


### 7.1 状态迁移

生命周期由应用级协调器持有。卡片卸载、分类变更和虚拟列表回收不能销毁资源。只有普通网页进入本章流程，插件、Harness、特殊内部页和终端继续服从其资源所有者。

| 当前状态 | 触发及校验 | 目标与动作 |
| --- | --- | --- |
| metadataOnly 或 sleeping | 当前有效的显式打开或 bulkVisible 需求 | 排队后 restoring，创建唯一新 guest |
| restoring | 本代实例已可展示 | live，交接展示并替换旧图 |
| restoring | 本代主框架有效失败或有界超时 | restoreStatus 为 failed；有实体则 live，无实体则回 metadataOnly 或 sleeping |
| live | 主区与侧栏均无真实展示入口 | 记录 idleSince，继续 live，撤销非必要采集 |
| live 且闲置 30 秒 | 仍无真实展示入口 | 仅标记闲置，不追加资源状态 |
| live 且闲置至少 5 分钟 | 用户允许且保护为 safe | suspending，执行保存和关闭事务 |
| suspending | 保存及复检通过且收到销毁证据 | sleeping，清理实例引用 |
| suspending | 新需求、保护变化、保存失败或拒绝关闭 | live，保留实例并记录原因 |
| 任意状态 | 用户关闭资源，经原所有者确认 | closed，拒绝迟到结果和新恢复 |

失焦不能单独启动闲置；必须确认所有有效真实展示入口均不存在。锁屏和宿主隐藏可使入口无效，但保活页面仍可能运行脚本、网络和后台工作。重新可见时取消旧闲置判定，不重新导航。

live 表示实体仍存活，不保证加载成功或可交互。失败后存活的 guest 继续纳入需求、闲置、保护和资源计数；有实体的重试优先复用，无实体才排队创建。失败不会使实例脱离回收管理，也不能通过 restoreStatus 为 failed 推断实例已经销毁。

计时保存 idleSince 和截止条件，定时器只负责唤起检查。每次回调核对当前代际、需求与保护。休眠唤醒后先刷新电源、窗口、可视和保护状态，暂停自动销毁与自动批量恢复直到一次有效状态刷新完成；不能根据迟到定时器连续处理全部页面。持续调宽和拖动期间延后销毁。

### 7.2 正面放行与保护记录

自动深睡须同时满足用户允许、资源类型合格、恢复元数据可保存、地址可安全重访、没有真实展示需求以及保护为 safe。GET 地址是恢复方式条件，不是可丢弃运行现场的证明。

保护记录包含 decision、reasonCodes、providerId、revision、checkedAt 和对应实例/导航代际。safe 来自经过测试的受控页面适配器或明确的可丢弃内容契约，默认有效期建议 2 秒，销毁前必须重新检查；有效期、适配器覆盖范围及事件来源由 P0 验证。普通未知跨站页面不能依靠未发现表单来获得 safe。

以下任一条件为 blocked：始终保持运行、编辑或未提交表单、beforeunload 拒绝、上传或文件交互、音视频播放和通话、录屏、DevTools、主框架导航或提交中、POST 结果、一次性令牌地址，以及资源所有者声明需保活。检测能力不足或适配器失效为 unknown。blocked 和 unknown 只阻止销毁，不阻止停止侧栏截图。

适配器属于应用受控边界，不接受网页任意消息直接授权关闭。将提供方及原因记录进诊断，不能为了提高深睡比例放宽安全结论。没有适配器覆盖的普通网站首版继续保活；P0 报告由此造成的收益范围。

### 7.3 保存与关闭事务

使用 suspendOperationId 绑定当前资源代际、导航版本、需求版本和保护版本。操作顺序如下。

1. 在资源协调器内核验无展示需求、无新恢复、未关闭且可安全重建；进入 suspending。
2. 获取稳定 taskId、resourceId、最终 URL、原 partition、zoom、尽力获取的滚动位置、恢复格式版本及记录时间。恢复记录不保存 Cookie、密码、POST 正文或页面 JS 堆。
3. 沿用现有持久化接口提交恢复元数据；写入失败回到 live，不能先卸载后补保存。
4. 提交后重新检查导航、需求、保护和交互状态。任何不匹配均撤销本次销毁；旧元数据可保留为旧版本，但不能冒充当前恢复状态。
5. 经当前 Electron 版本验证的 guest 关闭路径，尊重 beforeunload。不能先 React 卸载来绕过关闭。在 will-prevent-unload 中不调用用于强制放行的 preventDefault。[S1][source-s1]
6. 收到对应实例 destroyed 才提交 sleeping，清除 guest 引用、展示注册、采集租约和操作句柄。关闭被拒则回到 live；直到保护版本变化或显式用户操作才重试，避免循环关闭提示。

关闭已发出而用户新建展示需求时，不假定可以取消原生关闭。若原实例仍存活并拒绝关闭则复用；若已销毁则在销毁确认后按新需求排队恢复。未确认旧实例状态前禁止创建第二个 guest。关闭超时建议 5 秒，超时显示状态待核实并保留句柄，不能强杀受保护页面来解除阻塞。

### 7.4 恢复边界

沿用原 session 和 partition，避免错误账户或存储分区。登录有效性由网站决定；sessionStorage、内存令牌、表单与 WebSocket 不作通用恢复。首版只恢复当前 URL，历史栈能力留待当前版本专项验证。POST、一次性地址和受保护会话不自动重放或重建，显示需用户按原业务流程处理。

滚动恢复有界：主框架可展示后最多 3 次，在 2 秒内尝试，页面仍未稳定则停止并保持可操作。恢复过程中导航到新地址时终止旧滚动恢复。页面自身主动路由或滚动不应被无限覆盖。首版不新增贴图持久化，重启没有可用图片时使用标题、状态和占位。

## 8. 恢复队列与展示切换


### 8.1 需求来源与队列

恢复优先级为 explicitMain、explicitShelf、bulkVisible。前两者来自用户明确选择，bulkVisible 只由本次分类成功后的可视集合产生；列表曝光、补图和窗口尺寸变化不创建需求。主区请求独立于侧栏实时配置。

应用级恢复并发初始为 1，待处理资源初始上限 16，自动恢复驻留名额初始为 4。它们均为实验参数。队列只保存小型描述符，按资源合并需求；同代连续点击共用一个恢复 Promise，并可以提高优先级或更新展示目标。显示需要取消时只撤销该来源，其他有效来源继续保留。

出队和真正创建前重查 scope、任务存在性、当前代际、需求版本、展示资格和预算。过期请求直接取消。队列满时优先移除失效及低优先级自动请求；显式请求仍无容量时显示忙和重试，不能无界等待或覆盖其他用户正在使用的实例。

自动驻留名额只限制 bulkVisible 创建出的页面；资源被销毁或明确转为用户主动打开时按规则释放该名额。名额被 unknown 或 blocked 页面占用时停止新增自动创建，保留卡片。不能通过强制休眠保护页面腾名额，也不能声称此计数是整个应用的内存上限。

### 8.2 取消与超时

未创建的失效需求直接从队列删除。已创建或正在导航的 guest 必须由生命周期协调器持有并收尾，不能只忽略 Promise。失去展示需求时停止后续侧栏交接；若允许安全取消并销毁，则走同一保护协议，否则进入无展示保活，继续记账。不能强杀一个可能已产生表单或业务状态的页面。

建议导航等待上限 30 秒，首帧呈现等待 5 秒。超时结束自动等待与 UI 锁定，显示具体状态；若 guest 仍存活则保留受控引用，不把 timeout 等同于销毁。用户重试优先复用可用实例；确需替换时先确认旧实例已释放。不会同时启动多次自动重试，也不循环重建。

恢复并发许可覆盖创建和初始导航的真实在途阶段。UI 超时不提前归还许可；等导航实际完成、确认停止或实例销毁后才释放。原导航仍在进行时，重试先附着同一实例，不追加一次导航。长期悬挂时暂停自动恢复，显式操作通过原有导航控制或真实错误入口处理，不偷偷创建替代实例叠加资源。

### 8.3 可展示与业务就绪

恢复期间旧贴图保持可见，并禁止把点击坐标转发给还未交接的新页面。可展示需本代 guest 存活、几何有效、主框架导航结果有效及当前显示路径的首帧证据。截图若用于验证，也必须经过统一采集预算；优先采用当前版本可验证的呈现信号，不能为了证明 ready 绕过预算。[S1][source-s1]

可展示不等于业务恢复、登录有效或 SPA 初始化完成。受控适配器可以提供额外业务状态，普通网页只报告基础加载状态。首帧等待超时后提供显示当前页面或重试，避免旧贴图无限遮住已加载的登录页。只把当前代主框架的有效失败记为本次恢复失败；子框架错误、旧导航取消和已取代请求独立记录。

## 9. 贴图采集与缓存预算


### 9.1 采集资格和所有权

实时网页交互直接展示原生页面，周期截图只用于有实际预览需求的贴图入口。静态 Archive 不周期重采样；通知栏不参与。可视实时栏中的静态预览、必要的最后帧获取和恢复首帧验证统一进入应用预览调度，不允许多个组件各自保留定时器。

同一资源共用最近提交帧。缓存键含 scopeId、resourceId、instanceGeneration、navigationGeneration；geometryRevision 和 captureSequence 为更新版本，不按宽度创建无限键。每个资源最多一个提交帧，替换时临时持有新旧两帧并记入峰值。消费者使用引用租约，清理某个卡片不删除其他合法消费者正在使用的同一帧。

截图结果只可提交给仍有效的本代导航和尺寸。缓存中有旧帧不代表页面当前状态；显示快照时间和休眠、恢复中或错误状态。任务名称、状态和通知沿已有事件更新，不通过持续截图推断。

### 9.2 初始实验预算

以下数值为 P0 起始参数。软目标触发淘汰和降级；准入阈值约束应用能控制的持有及在途分配。它们不构成 Chromium、GPU 或进程总内存硬上限。

| 项目 | 起始参数 | 达到限制时的动作 |
| --- | --- | --- |
| 最终网页图像 | 不超过 960×600 物理像素，按显示尺寸生成 | 降低目标分辨率，不改原页面视口 |
| 解码帧与 Canvas | 64MiB 软目标，96MiB 准入阈值 | 释放离屏资源，必要时占位 |
| 编码图像 | 16MiB 软目标，24MiB 准入阈值 | 淘汰低优先级旧图，卡片保留 |
| 采集链临时预留 | 64MiB 准入阈值 | 容量不足不发起采集 |
| 单次原始截图 | 4,194,304 个物理像素 | 超限保留旧图或占位 |
| 原生截图在途 | 全应用预览路径最多 1 个 | 同资源合并，其余按优先级等待 |
| 截图等待项 | 最多 16 个资源描述符 | 丢弃失效及低优先级项 |
| 预览频率 | 有需求时先沿用约 500ms，事件驱动优先 | 不承诺高帧率传输 |

最终 960×600 的 RGBA 像素约为 2.2MiB，须按物理尺寸计算。DataURL 的 base64 字符及其 JS 表示、IPC 副本和图片解码须分别记录。原生库内部的暂时副本以实际测量和安全余量纳入准入估算，无法核实尺寸或成本时跳过采集。

### 9.3 采集流程

1. 获取当前完整视口、DPR、代际和采集需求；计算原图像素与原图、缩放、编码、传输、解码及新旧帧并存的预留成本。
2. 申请预算和唯一原生在途许可。预算不足先淘汰允许释放的缓存，再决定是否跳过，不等待期间持有大型原图。
3. 发起整幅可见页面的 capturePage。rect 是裁切区域，不是目标输出尺寸；无法在原图门槛内取得完整画面时跳过，不裁掉内容冒充完整截图，也不改变主区视口。[S1][source-s1]
4. 主进程可用且经版本验证时设置 stayHidden，避免截图改变隐藏语义；renderer 的 webview.capturePage 选项不同，须经受校验 IPC 调用正确入口，不能混用接口。[S1][source-s1] [S2][source-s2]
5. 结果返回后先检查实际尺寸、代际和需求，再缩放与编码。尺寸超过预估时停止后续处理、释放引用并熔断该来源，记录估算失准；已发生的原生分配仍要计入实际峰值。
6. 编码传输与消费者解码均在预算内完成，确认新图可用后替换旧图；释放旧图和在途额度。捕获、编码及解码流水线不能各自独立产生无界等待结果。

capturePage 失效或等待超时只能使结果不可提交，不能假定原生捕获已取消。原生在途许可必须等实际请求结束或匹配实例确认销毁才释放。建议 5 秒未完成即暂停新的预览采集并显示诊断，既有页面继续交互；禁止用 Promise.race 超时后立刻追加新请求，也不能为解除截图阻塞强杀活跃网页。

### 9.4 调宽和释放

拖动时内容框保持 16:9，对旧图使用 contain；旧画面比例不同可以留边。几何更新按帧合并，不在每个 pointermove 截图、编码或导航。尺寸稳定约 200ms 后，只更新存活且有许可的来源；休眠或仅有元数据的资源只缩放旧图，真正激活时用最新尺寸恢复。

离屏优先释放解码展示与 Canvas，保留预算允许的编码图；淘汰编码后使用标题、状态和占位。Canvas 清理后重置像素尺寸，清理 state、注册表、回调和 Promise 引用。首版先限制现有 DataURL 的所有权和数量；Blob/Object URL 作为独立实验，验证 CSP、IPC 和 revoke 生命周期后再替换，不扩大安全策略。[S4][source-s4]

后台绘制申请按资源与持有者登记，侧栏只释放自己的租约。主区、插件或其他合法持有者仍可保持需求。Electron 同窗其他 webContents 的 backgroundThrottling 设置可能影响整窗绘制，故以实际 CPU、合成与帧时间检验节省，而非仅统计定时器数量。[S3][source-s3]

## 10. Rust 原型与条件性迁移


### 10.1 进入条件

P0 必须先明确现有冷数据来源。封块只代表不再追加，不代表已脱离同步查询。如果整份 OutputBuffer 仍可能被 getRecentLines、getOutputSince 或 sendAndWait 同步读取，则保持同步查询、释放 JS 原文、异步解压不能直接同时满足。

允许两条路径：已有独立冷历史只迁移该范围；或者另行明确内部异步调用链改造，保持 MCP 对外字段与游标语义。没有这两个条件之一，停止生产迁移，只保留独立原型结论。禁止同步阻塞等待 Worker，禁止扩大日志保留量制造压缩对象。

首轮对比原实现、优化后的 TS/Node、Node 异步压缩与 Rust 编解码。优先用相同算法、压缩级别、块大小、保留量、队列和缓存；不同算法的结果单列。Node 异步 zlib 已使用内部线程池，Zstandard 是否可用以项目内嵌 Node 为准，不把纯 JS 同步压缩作为唯一基线。[S6][source-s6]

### 10.2 首选数据所有权

生产候选采用主进程有界仓库持有权威块、应用级共享 Worker 只执行编解码。Rust addon 只在 Worker 加载；renderer 通过现有 preload 和受校验 IPC 访问。首轮并发为 1，不为每个窗口或会话创建运行时。若最终不采用 Rust，同一仓库契约可由 Node 后端实现。

| 阶段 | 权威数据 | 临时数据及释放点 |
| --- | --- | --- |
| 封块 | 主进程保留原始块 | 未分配 Worker 输入 |
| 开始压缩 | 原始块仍可被现有保留策略管理 | 生成独占 UTF-16LE 缓冲并转移给 Worker |
| 编码中 | 原始块保持有效，或按原历史边界淘汰 | Worker 输入、输出及工作区全部记账 |
| 编码返回 | 校验前原始块仍是权威版本 | 返回独占编码缓冲，校验代际与内容身份 |
| 提交成功 | 主进程原子替换为压缩块 | 释放原文与 Worker 临时分配 |
| 冷块读取 | 主进程固定有界权威块快照 | 给 Worker 预算内副本；结果由消费者短期持有 |

不把唯一权威压缩块转移后留在 Worker。首版允许有界复制，不宣称零拷贝。必须采用已验证的独占 ArrayBuffer 路径；池化 Buffer 和共享视图的转移行为须以实际版本验证，不能把 transferList 当作无副本证明。[S5][source-s5]

### 10.3 格式和接口

载荷为 UTF-16LE 原始码元字节，可表示孤立代理项；不能经过有损 UTF-8 转换。原始块大小从 64KiB 字节开始，末块允许较小。块头包含 formatVersion、codec、codecParameters、storeEpoch、blockSeq、startCodeUnit、codeUnitLength、rawByteLength、encodedByteLength 和 checksum。

校验 rawByteLength 为偶数并等于 codeUnitLength 的两倍；游标加法、数组尺寸与块范围不得溢出。只允许白名单算法及参数。解压必须受原长、实际输出上限和工作区限制约束；高压缩率本身不能成为拒绝合法重复终端输出的唯一依据。压缩无收益时显式使用 raw 编码。

```ts
openStore(config): StoreHandle
appendSealedBlock(handle, epoch, seq, start, raw):
  Promise<CommitResult>
readRange(handle, epoch, cursor, limit):
  Promise<ReadResult>
trimBefore(handle, epoch, watermark): TrimResult
clearStore(handle, expectedEpoch): NewEpoch
stats(handle): StoreStats
closeStore(handle): Promise<void>
```

这些是仓库设计接口。Worker 仅提供 encode、decode 和协作式 cancel，不自行修改任务状态、决定历史淘汰或更新游标。R2 搜索与 R3 清洗另行评估；跨块 ANSI、CR、退格、换行与代理项语义按旧实现验证，不用独立清洗每块再拼接替代状态化解析。

### 10.4 提交与并发规则

主进程是唯一历史写入者。storeEpoch 区分 clear 前后，blockSeq 标识块，trimWatermark 单调推进。append 的成功 ACK 代表校验与替换已提交；开始压缩不代表成功。结果只可替换仍存在且代际、块身份和原始内容版本匹配的块。

CommitResult 至少区分 stored-raw、stored-compressed 和 superseded。队列满且原文已被既有仓库接纳时完成为 stored-raw；压缩期间被正常保留策略淘汰时完成为 superseded；clear 或 close 取消以明确错误完成。每个请求恰好完成一次，不能因没有进行压缩而永久等待。成功状态描述已完成的存储方式，不把正常淘汰误报为存储故障。

trim 立即推进逻辑可读边界；迟到压缩不能复活被淘汰内容。边界在块内时可暂存整块及逻辑偏移，但额外持有量计入预算。clear 递增 epoch 并使旧读写失效。close 先拒绝新请求，再取消、释放和幂等完成，不能影响 PTY。

readRange 固定请求开始时的上界和必要块，形成有界快照；后续 trim 影响新请求，已有快照可按约定完成，clear 和 close 则使旧请求失效。内部字段不得擅自进入 MCP 公开格式。若现有查询行为与该快照语义不一致，应在 P0 查明后调整接口并重跑一致性测试，不能直接改变用户语义。

### 10.5 预算与队列满

对热尾、原始块、压缩块、块索引、解码缓存、读快照、返回结果、编解码工作区及容器保留容量统一记账。预算先预留再分配，不只统计 Vec.length 或已提交块。初始每次原始块 64KiB、并发 1，队列条目可从 16 开始；总字节上限由现有保留量及实测工作区决定，不能默认增加可保留历史。

队列满时不生成额外编码副本，原文留在现有有界缓冲并按原策略淘汰；终端输出不等待压缩，不改变 ACK。读取超过批准范围时按现有接口的限制处理，不以无界解压满足请求。配置必须容纳允许的未压缩退化路径；无法容纳时拒绝启用迁移，不能静默缩短保留量。

取消只有在 Worker 确认结束、任务返回或 Worker 退出后才归还实际在途额度。应用预算不依赖 Worker.resourceLimits 来限制原生分配；该选项不覆盖 ArrayBuffer 等外部数据。[S5][source-s5]

### 10.6 故障与回退

主进程仍存活时，普通 Worker 异常退出不会丢失当时仍在既有保留范围内的已提交权威块；仍在该范围内的未提交块继续使用原文。已正常淘汰的内容不恢复，截断状态按既有语义返回。受影响读取返回真实错误或转兼容后端进行至多一次有界重试。每种进入生产的编码都必须有可独立于 Rust addon 工作的解码路径；没有兼容解码的算法只留在原型。

编解码超时使该 Worker 停止接纳新任务并进入故障状态，受影响请求按规则返回错误或在统一剩余预算内转兼容后端。同步原生调用可能无法及时处理 cancel 或 terminate，超时不能释放尚未结束的原生分配，也不能直接新建替代 Worker 叠加资源。closeStore 分别确认逻辑关闭与实际清理完成；界面和任务控制不等待无法中断的原生调用，迟到结果按关闭状态丢弃，悬挂分配继续计账和诊断。

回退关闭新的 Rust 编码，旧压缩块继续由兼容后端按需读取。需要迁回原始格式时逐块替换、预算内运行，不一次性展开全库。同进程原生崩溃与进程级 OOM 不在普通 Worker 隔离保证内；若要求编解码原生故障不得直接影响主进程，使用 utilityProcess 等进程边界并重新测量。utilityProcess 是 Node 入口，独立 Rust 程序须使用相应子进程协议。[S5][source-s5] [S9][source-s9]

Node-API 的 ABI 稳定性不等于所有原生依赖自动兼容。验证 Windows x64 的实际 Electron 安装包、Worker 入口路径、native 文件位置、缺失模块、退出、重启和卸载；其他受支持平台逐一验证。不改变 renderer 沙箱或既有 native 模块 ABI 配置。[S10][source-s10]

### 10.7 放行条件

- 数据与查询一致性全部通过，原保留量、游标和终端行为不变。
- 相同负载下，应用相关总私有内存下降超过重复测量波动，报告绝对 MiB、相对值与峰值。
- 净收益包括 Worker 基线、模块、索引、解压缓存、原生工作区和跨边界临时副本。
- 冷读取、输入响应、界面长任务和小数据场景满足 P0 后冻结的体验阈值。
- 所有发布平台加载、故障诊断和兼容回退通过；新增依赖与维护成本有记录。

当 Node 方案达到目标而 Rust 没有额外净收益时，交付 Node 实现并结束 Rust 试点。Rust 长期持有唯一历史、R2 索引搜索、R3 ANSI 清洗或新增磁盘存储均属于新的范围决定，不能顺带上线。

## 11. IPC 与参数配置


### 11.1 边界校验

新增命令同时更新 shared 类型、main handlers、validation、preload 和消费者。renderer 传递任务与资源逻辑 ID，不传原生指针或直接访问 addon。主进程根据发送方核验 scope 和资源所有权，不能信任客户端声称的 generation、分类或展示状态；代际用于拒绝过期操作，不能替代权限校验。

分类载荷校验 bootId、requestId、唯一任务 ID、版本和条目上限；范围读取校验安全整数、码元上限、句柄生命周期和返回长度。大批次按仓库登记的不可变快照分片，禁止因为 IPC 单包上限漏掉任务。截图 IPC 只允许指定的本代资源和批准参数，不能允许任意 webContents ID 截图。

错误类型至少区分 NOT_FOUND、CONFLICT、STALE_GENERATION、STALE_DEMAND、INITIALIZATION_BLOCKED、BUDGET_EXCEEDED、PROTECTED、TIMEOUT、LOAD_FAILED、PERSIST_FAILED、CODEC_FAILED、CLOSED。内部诊断可详细记录，用户界面提供准确原因与适用的重试入口，不把所有错误合并成加载失败。

### 11.2 配置与功能开关

时间、预算和并发集中在单一配置定义，写明单位。运行时使用已校验的只读配置快照，变更后推进策略版本。对减小预算只淘汰可释放缓存并停止新增分配，不能强制销毁受保护资源。

建议配置项如下，名称均为设计字段。

| 配置 | 默认或起始值 | 生效边界 |
| --- | --- | --- |
| realtimeView | tasks | 发布首版可设 none |
| autoHideDelayMs | 350 | 交互保护解除后才计时 |
| resizeSettleMs | 200 | 只影响按需截图 |
| idleLabelMs | 30000 | 诊断标签 |
| deepSleepAfterMs | 300000 | 仅触发保护检查 |
| restoreConcurrency | 1 | 应用普通网页恢复队列 |
| restorePendingLimit | 16 | 合并后的资源条目数 |
| autoRestoreResidentLimit | 4 | bulkVisible 自动创建 |
| navigationTimeoutMs | 30000 | 超时不等于销毁 |
| firstPresentationTimeoutMs | 5000 | 提供显示当前页面入口 |
| captureConcurrency | 1 | 真实原生在途请求 |
| capturePendingLimit | 16 | 失效和低优先级项淘汰 |
| captureWatchdogMs | 5000 | 熔断新采集，不假取消旧请求 |
| frameMemoryPolicy | 第 9 章预算 | 物理像素和字节 |

功能开关建议为 startupArchive、activationCommands、presentationCoordinator、frameBudget、safeBrowserSleep、nativeHistoryCodec。开发和灰度默认关闭未验收阶段；验收后逐项启用。safeBrowserSleep 还须逐资源获得策略许可与适配器 safe 证据，开启总开关不会覆盖保护。nativeHistoryCodec 没有通过原型放行时保持关闭。

开关关闭后停止产生新操作，已经开始的操作由原协调器安全收尾。不能通过卸载协调器使未完成 guest、Promise 或预算凭据失去所有者。

## 12. 文件改动计划与协作边界


文件路径是实施定位清单，不是已经完成的修改。P0 应把现有名称、测试位置和调用者补成仓库内的最终范围。涉及并行帧同步任务的文件，先约定所有权或采用最小接口接入，不覆盖其他任务的未提交修改。

| 范围 | 现有入口或建议新增模块 | 主要改动 |
| --- | --- | --- |

新增模块优先采用现有依赖和测试框架。只有 Rust 阶段放行后才引入原生构建依赖；原型代码独立于生产构建，不能因目录存在就自动打包。资源释放集中在对应所有者，不在多个 React effect 内分别猜测是否 dispose。

## 13. 分阶段实施与交付


### 13.1 P0 基线和协议核对

范围为第 3 章的隔离测量、源码及版本能力核对。交付可重复运行的脚本、固定 fixture、原始结果、统计报告、数据所有权图、冷数据清单和最终实验参数。完成条件是最大内存来源明确、现有任务保存语义清楚、主区和侧栏实例归属已核实。若只能读取代码而无法运行隔离 Electron，应明确留下未验证项，不能用无关构建替代实测。

### 13.2 P1a 启动归档和激活

只修改任务仓库命令、启动协调与必要 UI 结果。先验证启动快照和保存屏障，再实现单个及全部激活。交付分类操作协议、冲突和部分失败反馈、恢复独立入口。此阶段可先保持所有卡片静态，确保不会因分类自动执行任务。完成条件为重启、刷新、连点、同项重归档和保存失败均符合第 5 章。

### 13.3 P1b 展示仲裁和侧栏交互

引入主区优先的唯一真实展示位置，接入 tasks 与 none 的实时策略，拆开点击、选择、展开和资源状态。实现有效区域与 350ms 收起，保留编辑、IME、键盘、拖动和菜单保护。交付主区与侧栏同资源的集成用例和中文输入视觉验收。完成条件为同实例复用、不重复订阅、不误 resize、不误失焦，所有侧栏旧租约可核对释放。

### 13.4 P1c 缓存与调度

把所有预览入口纳入同一个预算和采集调度，限制原图、最终图、编码及在途阶段；实现尺寸版本、失效结果、LRU、占位及采集熔断。此阶段不启用自动深睡。交付与基线相同工作负载的 CPU、原图峰值、缓存命中、跳过原因和内存对照。完成条件为全部卡片可访问，截图不唤醒页面，悬挂请求不会产生第二个原生采集。

### 13.5 P2a 有界恢复

接入元数据展示、显式恢复、一次 bulkVisible 需求、出队复检、同代合并与自动驻留名额。处理导航、首帧、错误和超时收尾。交付重启不创建网页、单个激活、全部激活后收栏、快速切换和离线场景。完成条件为没有重复 guest、没有迟到抢焦点、没有因滚动或补图批量加载。

### 13.6 P2b 安全深睡

先为受控页面实现并验证保护适配器，再启用 5 分钟候选、保存复检、尊重 beforeunload 的关闭和销毁确认。unknown 页面保持运行。交付适配器能力清单、可休眠内存覆盖率、拒绝原因、锁屏唤醒及 100 轮循环结果。完成条件为受保护页面零误休眠、保存失败不释放、拒绝关闭不强杀。

### 13.7 P3 Rust 独立原型

只有在原型工作范围获得确认后安装所需工具链和依赖。原型不连接生产 PTY、xterm 或持久任务，使用固定日志和实际 Electron 构建环境。交付同算法对照、UTF-16 一致性、字节所有权、Worker 故障和安装包加载结果。没有可迁移冷数据时仍可完成实验报告，但明确停止 P4。

### 13.8 P4 条件性迁移

满足第 10 章所有放行条件后，才将已确定冷范围接入统一仓库。若涉及内部同步到异步改造，逐调用链列入范围并保持 MCP 对外格式和游标行为。交付兼容解码、回退开关、预算、并发操作一致性及平台烟测。R2、R3 不随此阶段自动启用。

### 13.9 P5 联合验收与发布

按相同数据与负载执行原版、仅调度缓存、加入恢复深睡、再加入历史后端四组对照，分别说明收益来源和恢复代价。先在隔离档案运行，再在获授权的灰度范围启用。每阶段改动以独立提交或可独立回退单元交付，合并实际帧同步任务的验证结果。出现数据丢失、任务重执行、受保护页面误销毁或重复实例时停止放行。

每个功能阶段开始前，按原有约定提供实际文件范围、依赖、数据变化和验收方式供确认。文档编写与本方案交付不构成上述功能修改的执行批准。

## 14. 测试矩阵与判定标准


### 14.1 分层验证

纯逻辑测试覆盖策略、版本、预算、快照批次、计时和编解码，使用可控时钟与事件顺序。真实隔离 Electron 验证 guest 创建销毁、跨 webview 输入、截图及 beforeunload；中文输入、拖动、DPI 和视觉切换必须进行实际交互检查。不能用模拟 DOM 结果证明原生 guest 已释放。

### 14.3 正确性与性能门槛

正确性采用硬门槛：任务和记录零意外丢失、零命令重执行、零受保护页面误销毁、零幽灵卡片、同资源零重复认可实例；所有队列与应用可管理缓存满足配置边界。这些失败不能用平均内存下降抵消。

性能采用 P0 后冻结的场景门槛：稳态和操作峰值总私有内存分别比较，输入与恢复 p50/p95、长任务和实际帧时间分别报告。建议首轮以交互 p95 不超过基线的 110% 作为候选门槛，并同时设合理绝对容差，避免极短基线被测量噪声支配；最终值必须结合样本波动确认，不能写成已达到。低内存设备、无冷历史和少量页面场景单列，避免总体均值掩盖负收益。

恢复深睡应同时报告内存下降和重新加载代价。全部激活的分类完成时延与可交互时延分开。Rust 必须与优化后的 Node 后端比较，报告额外固定成本，不因 JS heap 转移到 native 而放行。rAF 回调频率不能代表实际呈现帧率，帧同步任务结果独立核验后合并。

## 15. 监控与故障处置


### 15.1 最小诊断项

每次操作记录 scope 内的逻辑资源标识、requestId、相关版本、触发来源、结果原因、队列耗时及持有字节；日志采用有界缓冲或既有有界日志机制。生产诊断不记录终端正文、Cookie、密码、POST 正文或带敏感查询参数的完整 URL。

核心计数包含 live 和 restoring guest 数、自动恢复驻留数、待恢复和待截图数、真实原生截图在途数、各预算已用及预留、缓存命中和淘汰、过期结果丢弃、保护拒绝原因、启动归档提交结果及历史后端故障次数。计数来自所有者，不通过各组件各自统计后相加。

### 15.2 故障处理表


| 故障 | 即时处理 | 后续动作 |
| --- | --- | --- |
| 任务保存失败 | 保留真实记录与分类，不发布成功 | 用户重试或修复原仓库问题 |
| 保护为 blocked 或 unknown | 保活，仅停止非必要采集 | 等保护变化，不强行释放 |
| 页面恢复失败 | 保留贴图或占位，报告真实原因 | 用户重试或显示当前页面 |
| guest 崩溃 | 标记实例失效，清理相关租约 | 按原协议及显式需求恢复，不重放任务 |
| 截图长期未结束 | 熔断新增采集，保留原生在途记录 | 请求结束或销毁证据后恢复调度 |
| 缓存达到准入阈值 | 淘汰可释放资源或跳过新采集 | 保留卡片，不唤醒补图 |
| 普通 Worker 异常退出 | 停止新编码，保留权威块 | 兼容读取，至多一次有界重试 |
| native 进程级故障 | 遵循已明确的故障模型 | 需要更强隔离时改进程架构再评估 |

网页或历史功能异常只停相应优化，不以自动重启用户软件、共享后端、shell 或 Agent 作为修复手段。

## 16. 发布与回退


### 16.1 发布顺序

每阶段先检查与并行任务合并后的实际代码，再运行对应验证。灰度期间保留功能开关与原因计数。P1a、P1b、P1c、P2a、P2b 分别放行；Rust 不阻塞 TS/Electron 阶段完成。发布记录写明应用提交、配置、支持页面范围、测试环境和未覆盖平台。

新增保存字段必须兼容旧记录。需要数据格式升级时使用现有仓库迁移机制、版本校验与可核对的迁移结果；没有迁移授权时维持旧格式。首版不新增磁盘贴图库，不把测试 fixture 或测量日志写入用户任务数据。

### 16.2 回退行为

关闭启动归档开关只影响后续启动，不把本次用户已移动的记录自动改回旧分类。关闭自动深睡后停止新销毁，已睡眠页面仍按显式需求恢复，不批量唤醒。关闭缓存或调度新策略时，先排空或安全接管在途操作，避免双定时器和双所有者同时存在。

关闭 Rust 后停止新 Rust 编码，已有块用兼容解码读取；有界逐块迁回是可选后续操作，不要求立即全库解压。没有兼容读取能力的编码从一开始就不能进入生产。所有回退保留任务 ID、仓库记录和实际运行状态，不重新执行任务。

### 16.3 每阶段交付清单

- 实际变更文件与提交，明确与其他任务的接口和文件归属。
- 配置、依赖及数据格式变化，必要时提供兼容和迁移说明。
- 自动测试结果、真实 Electron 集成结果、中文输入和视觉验收记录。
- 相同场景的基线对照及限制，包括稳态、峰值、恢复和少量资源场景。
- 功能开关、故障定位和回退步骤，确认关闭优化不停止后台任务。
- 更新相关设计说明；实施启动展示策略时同步 docs/task-shelf-plan.md，保留既有连接续接边界。

## 17. 首轮开发任务与完成定义


首轮开发只推进 P0，并根据其结果冻结 P1a 到 P2b 的文件范围和参数。P0 的核心问题是实际占用来自哪里、哪些资源可以安全释放、哪些历史副本能够被替换。没有证据时保持保守行为，不以先引入 Rust 或先卸载所有网页替代测量。

完成本方案需要同时满足功能正确、资源生命周期有界和收益可复现。任务数量、任务执行、输入输出和审批行为必须保持正确；静态图、恢复中与失败状态必须与真实状态一致；节省总内存的代价必须以恢复时间和交互延迟呈现。某一可选阶段无收益时可以形成明确的停用决定，这属于有效交付，不要求为满足语言选择而扩大范围。

### A2 出队再次校验

```ts
async function processRestore(request) {
  const now = coordinator.current(request.resourceId);
  if (!demandStillValid(request, now)) return cancel(request);
  if (now.liveInstance) return presentIfOwned(now);
  if (now.pendingRestore) return join(now.pendingRestore);
  const permit = budgets.tryReserveRestore(request, now);
  if (!permit) return deferOrReportBusy(request);
  // 创建前仍在协调器的同一受控临界区内。
  if (!demandStillValid(request, coordinator.current(now.id))) {
    permit.release();
    return cancel(request);
  }
  return coordinator.startOwnedRestore(request, permit);
}
```

### A3 休眠前后复检

```ts
async function trySuspend(resourceId) {
  const operation = coordinator.beginEligibleSuspend(resourceId);
  if (!operation) return;
  const saved = await metadata.save(operation.restoreRecord);
  if (!saved || !coordinator.revalidate(operation)) {
    return coordinator.keepAlive(operation);
  }
  await coordinator.requestRespectfulClose(operation);
  // sleeping 只由匹配本代的 destroyed 事件提交。
  // timeout 不释放旧实例身份，也不创建替代 guest。
}
```

### A4 历史压缩提交

```ts
async function encodeSealedBlock(block) {
  const reservation = budget.tryReserveWorstCase(block);
  if (!reservation) return keepExistingBoundedRaw(block);
  const token = history.captureBlockIdentity(block);
  try {
    const encoded = await codec.encode(copyForWorker(block));
    if (!history.canReplace(token)) return discard(encoded);
    validateEncodedBlock(encoded, token);
    history.commitEncodedReplacement(token, encoded);
    // 只在 commit 后释放原始权威副本。
  } finally {
    // 真实任务完成或确认退出后才释放在途额度。
    reservation.releaseAfterActualCompletion();
  }
}
```

以上伪代码表达顺序和所有权，不是可直接粘贴的现有 API。错误、取消和 finally 的实现必须遵循正文的真实完成语义。
