源码基线：`df21fb45a4e4721faaec1c391aad45ac4ab1d777`。下列行号对应此版本；报告中的缺陷是该版本已有问题，尚未实施修复。

## 结论与证据边界

现有机柜、卷轴、印章视觉具有产品辨识度，值得保留。主要问题集中在异步状态一致性、失败恢复、键盘操作和主题文字色阶。建议先修影响操作正确性的问题，再统一组件交互基础，最后做视觉微调。

两份独立源码评估已完成，并核对重点发现。机械检查执行 `impeccable.cmd detect --json src/renderer/components`，退出码 0，输出 `[]`。检测器零命中不代表键盘、异步返回契约或对比度合格；下列问题均经源码核实。

没有对当前 Electron 窗口进行实时操作、NVDA 测试或 React Profiler 实测。查看了仓库主界面和主题截图，但主图显示 v1.0.8，且部分布局已与源码不同，仅作历史参考。对比度数字依据源码前景/背景色计算；实际渲染仍需确认。性能项是可确定的订阅范围问题，不能据此断言应用卡顿。

## 优先问题

### 1. P1 文件列表异步结果可能覆盖当前服务器

位置：`src/renderer/components/FileManager/FileManagerPanel.tsx:149`、`:186`、`:192`、`:201`。

触发：A 的请求未返回时切到 B，或者同服务器连续切换目录，旧请求后返回。`currentServerKey === key` 使用发起请求时的闭包，无法验证返回时的当前身份；home 请求也直接写显示路径。可能出现 B 会话下显示 A 的文件/路径，而下载动作使用 B 的 sessionId。

建议：维护最新活动身份引用和请求序号，校验服务器、会话、目标目录；旧结果可写对应缓存，但不能覆盖当前显示。同目录 MD5 请求也应遵循该规则。修复后用可控延迟测试 A→B 和目录 X→Y 的乱序返回。方向：`$impeccable harden`。

### 2. P1 快捷命令保存失败仍关闭编辑框、清空草稿

位置：`src/renderer/components/QuickCommands/QuickCommandsPanel.tsx:195`、`:210`。后端返回依据：`src/main/ipc/handlers.ts:953`、`:962`、`:972`。

新增、更新、删除返回业务失败对象时，组件未检查结果，仍刷新、关闭和 reset。invoke 拒绝也缺用户可见处理。

建议：区分新增成功对象与更新/删除的 success 返回；失败时保留编辑内容并展示错误，成功后再关闭，提交期间禁用重复操作。方向：`$impeccable harden`。

### 3. P1 核心连接、启动、进入目录和页签切换入口缺键盘路径

位置：`src/renderer/components/Layout/SessionsPanel.tsx:388`、`AgentsPanel.tsx:423`、`HarnessPanel.tsx:638`、`PaneTabBar.tsx:916`；`src/renderer/components/FileManager/FileBrowser.tsx:229`、`:338`。

主动作使用带 onClick 的 div/span，未提供聚焦与键盘激活。Tab 可以到编辑/删除按钮，却不能直接启动对应卡片；目录浏览也依赖鼠标。涉及键盘操作要求 WCAG 2.1.1。

建议：把主动作与次按钮分离，使用原生按钮或明确的键盘模型，提供 Enter/Space 激活；页签增加方向键和选中语义。不要把含按钮的整行改成嵌套 button。可参考已有 PanelTabs。方向：`$impeccable harden`。

### 4. P1 弹窗缺模态边界，表单标签未完整关联

位置：`src/renderer/components/SessionDialog/SessionDialog.tsx:754`、`:1089`；`ExportImportDialog/ExportImportDialog.tsx:309`；`Layout/AgentsPanel.tsx:555`、`EnvProfilePanel.tsx:594`、`HarnessPanel.tsx:977`、`PluginViewDialog.tsx:58`。

遮罩与 useEscDismiss 只负责视觉和 Escape；未建立 dialog 语义、Tab 圈定、关闭恢复和背景隔离。AgentsPanel、EnvProfilePanel、HarnessPanel 的名称输入已有 autoFocus，但尚未形成完整的模态焦点生命周期；SessionDialog、ExportImportDialog、PluginViewDialog 未见显式初始聚焦。SessionDialog 的 FieldRow 用 span 呈现标签，没有给关联输入建立可访问名称。涉及 WCAG 2.4.3、3.3.2、4.1.2。

建议：抽共享 DialogShell，统一焦点生命周期、标题关联和背景 inert；逐字段补 label/aria-labelledby。插件 webview 的宿主与 guest 焦点需单独验证。方向：`$impeccable harden`。

### 5. P1 浅色主题 SSH 输入聚焦后切成白字

位置：`src/renderer/components/SessionDialog/SessionDialog.tsx:985`、`:1002`。

用户名与密码输入使用 `focus:text-white`，背景透明。Paper rack 底色 #EBEBEB 与白色对比约 1.19:1，Lark #EDEEF0 约 1.16:1，远低于普通文字 4.5:1（WCAG 1.4.3）。

建议：聚焦继续使用 --text-rack，以边框/caret 或轻背景变化表达状态。方向：`$impeccable colorize`。

### 6. P1 浅色主题传输状态文字对比不足

位置：`src/renderer/components/FileManager/DownloadProgressBar.tsx:153`、`:164`、`:191`、`:199`。

状态文字和完成文件名使用亮色 --live/--error-rack；Paper rack 底上的绿字约 1.48:1、红字约 2.33:1，不适合普通大小文字（WCAG 1.4.3）。

建议：拆分状态文字色与指示点/进度条色；浅色主题文字使用更深的语义色阶，保留原亮色用于图形。其他有实际含义的 faint 提示也需一起测量，不能只看主题选择器。方向：`$impeccable colorize`。

### 7. P2 MD5 缓存跨服务器复用，失败后无重试

位置：`src/renderer/components/FileManager/FileBrowser.tsx:103`、`:117`；父组件 `FileManagerPanel.tsx:441`。

缓存仅以 file.path 为键，组件切服务器不重挂；相同路径会沿用另一服务器的 hash。失败哨兵也被当作已缓存值，后续点击仅切换展开状态。

建议：缓存身份包含服务器、路径及文件变更信息；失败展示重试，文件刷新/变化后失效，丢弃旧身份返回。方向：`$impeccable harden`。

### 8. P2 启动、删除及设置持久化的失败反馈不一致

位置：`src/renderer/components/Layout/AgentsPanel.tsx:259`、`HarnessPanel.tsx:563`、`SettingsPanel.tsx:120`。

自定义 Agent 启动忽略失败返回；工作区编辑框删除忽略 success 后关闭；下载目录先更新显示再 await 保存，没有失败回滚或用户提示。用户无法确认操作是否真正生效。

建议：对齐已有 actionError/saveError，保留失败现场；设置先保存成功再确认，或提供回滚。异步流程同时处理业务失败和 invoke reject。方向：`$impeccable harden`。

### 9. P2 文件列宽超过最小侧栏宽

位置：`src/renderer/components/FileManager/FileBrowser.tsx:344`；侧栏下限 `Layout/MainWindow.tsx:50`。

固定轨道 175px，加 5 个 8px gap 与右内边距，文件名尚未计入就需约 225px；侧栏允许拖到 180px。窄栏会挤压文件名或产生溢出。

建议：按组件容器宽度隐藏时间/大小列，窄栏用文件名+操作的紧凑布局。验证 180/240/320px 和英文、长文件名。桌面应用无需因此添加手机布局。方向：`$impeccable adapt`。

### 10. P2 插件宿主引用未定义主题变量

位置：`src/renderer/components/Layout/PluginViewDialog.tsx:59`、`:63`、`:69`；`PluginViewPanel.tsx:67`。

--border-base、--text-base、--text-dim 在 src 中没有定义，相关 CSS 声明失效，边框和文字依赖默认值或继承。

建议：映射到 --rule、--text-rack、--text-rack-mute；同步主题化分屏条的旧蓝灰色和导入导出框的旧配色，保持原有结构。方向：`$impeccable colorize`。

### 11. P2 分屏调宽只有指针路径

位置：`src/renderer/components/Layout/SplitDivider.tsx:66`。

分隔条不可聚焦，没有 separator/value/orientation 语义与键盘步进。已有 pointer cancel/lost capture 清理正确，无需重做。

建议：参考 `src/renderer/components/DocPanel/OutlineRail.tsx:254` 的可聚焦分隔条，提供方向键、Home/End 与可见焦点；命中区域可增大而保持细线外观。方向：`$impeccable harden`。

### 12. P2 宽泛 store 订阅造成无关更新通知

位置：`src/renderer/components/Terminal/TerminalView.tsx:173`、`:174`；`Layout/SessionsPanel.tsx:529`；`FileManager/FileManagerPanel.tsx:92`、`:93`。

整个 store 订阅会随不相关会话的可达性/活动标记变化更新。多个终端时有优化空间，但尚无卡顿或帧率实测证据。

建议：动作采用字段 selector，终端按 sessionId 选择所需 entry/字段，避免无变化也重建状态。先用 Profiler 记录多终端与侧栏拖动，再比较改动收益；不必一律添加 memo。方向：`$impeccable optimize`。

### 13. P2 环境变量输入焦点不明显，筛选空态会误导

位置：`src/renderer/components/EnvRowsEditor.tsx:119`、`:130`；`FileManager/FileBrowser.tsx:329`。

环境变量输入移除 outline 且没有替代焦点状态；文件筛选无结果与真实空目录共用“空目录”，会使用户误判远端内容。

建议：变量行添加 focus-within/输入 focus-visible，并给 KEY/VALUE 明确标签；空态区分加载失败、空目录和筛选无结果，后者提供“清除筛选”。方向：`$impeccable harden`、`$impeccable clarify`。

### 14. P3 错误兜底可以更局部、更一致

位置：`src/renderer/components/ErrorBoundary.tsx:34`；`src/renderer/main.tsx:32`。

根级错误边界已能防全局黑屏，值得保留。目前兜底硬编码中文与暗色，恢复只有全页重载。

建议：在文档/插件等可独立故障区域评估局部边界，提供区域重试；根级兜底用初始化可用的语言与主题。先核对重载是否影响会话体验，再决定恢复文案。方向：`$impeccable harden`。

## 实施顺序与验收

1. `$impeccable harden`：先处理文件请求竞态、快捷命令失败、MD5 隔离和业务失败反馈；为乱序响应与失败保留草稿补有意义的回归测试。
2. `$impeccable harden`：统一 DialogShell、主操作键盘入口与字段标签。用键盘完成连接、启动、目录浏览、关闭弹窗与返回原焦点，并验证 IME/Escape 不回归。
3. `$impeccable colorize` + `$impeccable adapt`：修浅色焦点和状态文字、未定义 token、窄侧栏。一次批量检查 Paper/Lark/主要暗色主题及实际最小窗口/侧栏/分屏尺寸。
4. `$impeccable optimize`：依据 Profiler 收窄订阅；没有数据支持时不额外重构大型组件。
5. `$impeccable polish`：统一焦点、错误条、状态提示和空态文案，保留现有水墨视觉。修复后再运行 audit 核对改善。

这些优化可以分批实施，也可以按上述顺序一次处理。PRODUCT.md/DESIGN.md 当前缺失，属于上下文文档空缺，不阻断现有界面的修补；以后有新界面或重设计需求时，可通过 `$impeccable init` 补齐。
