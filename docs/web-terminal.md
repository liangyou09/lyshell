# 网页 SSH 终端工具

在 LyShell 的普通网页页签内打开堡垒机等现有 Web SSH 服务。网页及其服务端仍负责登录、SSH 连接、回显和重连；LyShell 提供本地命令草稿和输入工具，不另建 Web SSH 服务。

## 使用

1. 在网页中登录并打开 SSH 终端。第一版支持 xterm.js，包括 iframe 内的终端。
2. 展开页签下方的「网页终端」。先点击网页终端的输入区域，再点「绑定所选终端」。无法识别时不向普通表单输入。
3. 输入命令、从下拉框载入已有快捷命令，或导入 UTF-8 文本脚本。侧栏快捷命令和 Ctrl+F1–F12 也会载入当前网页页签的草稿；不会发送到网页后面隐藏的本地 / SSH 终端。网页命令按字面输入，不解析快捷命令的终端控制字符转义。
4. 「输入一行，不回车」适用于单行命令；「逐行执行」逐行输入并回车，保留缩进与空行。行间隔可设 50–3000ms，默认 150ms。它只限制输入速度，不等待命令执行结束，不读取远端退出码。长耗时命令、交互提示和敏感操作应在网页中观察并分段发送。
5. 「停止后续发送」停止尚未发送的行。已发送的命令可能仍在远端执行；需要终止远端进程时，请在网页终端内操作。

草稿随当前页签保留在内存中，切换页签、分屏或拖动不会主动刷新网页。关闭页签或退出应用后不恢复草稿。导入文件最多 64 KiB；草稿最多 65536 个 UTF-16 字符，每行最多 16384 字符。不接受 NUL、ESC 等终端控制字符。

## 弱网行为与边界

- 发送过程逐行串行，不自动重试。停止、切换活动页签、宿主收到网络离线通知时，停止后续输入。
- 页面 / iframe 导航、SPA 路由变化、终端被替换或页面崩溃后，绑定失效，需重新点选并绑定。
- 发送失败可能发生在部分文本已输入之后。界面显示结果不确定，用户应先检查网页，避免重复执行。
- 「已输入」只表示输入桥交付给网页，不表示 SSH 服务收到、远端命令成功或执行完成。
- 浏览器的在线状态不能证明堡垒机 WebSocket 或 SSH 链路连通。第三方网页自身的断线提示、重连与会话恢复仍以该服务实现为准。LyShell 不替第三方页面保活 SSH，也不在网络恢复后重放命令。
- 非 xterm.js 的自定义终端暂不适配，页面也可能限制外部输入。普通网页表单、密码输入框、插件页与官方 Harness 工作台不能作为输入目标。

## 实现入口

共享请求与验证位于 `src/shared/web-terminal.ts`；主进程输入桥位于 `src/main/browser/web-terminal.ts`，由 `src/main/ipc/handlers.ts`、`src/main/ipc/validation.ts` 和 `src/preload/index.ts` 接入。界面与逐行发送位于 `src/renderer/components/Layout/WebTerminalTools.tsx`。输入请求只交付给同一主窗口拥有的普通网页 guest，不暴露任意脚本执行接口。

输入在已绑定 frame 内通过 xterm 的粘贴与回车事件交付，遵循终端的 bracketed paste 模式，不占用系统剪贴板。命令仅经 JSON 序列化作为固定函数的数据参数，不能执行为 JavaScript。每次输入同时核对绑定 token、文档地址、原终端元素引用和截止时间；复制相同 DOM 标记的新元素不能接管旧绑定。

此路径避开了当前 Electron 在跨域 iframe 中原生 `webContents.insertText` 可能导致渲染进程崩溃的问题。严格拒绝合成事件或采用自定义输入机制的网页仍可能不兼容；需要在实际堡垒机上核对。
