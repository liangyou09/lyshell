# 右侧任务保存区：持续保存与现场续接方案

日期：2026-10-28。状态：收纳、动态保存、归档、右键菜单、可配置快捷键与本地独立宿主已实施；退出时结束运行并归档 Tasks，启动以固定快照补归档，不再跨应用退出保活。新增版本校验的单个/全部激活、Tasks/Static 策略、普通网页恢复队列与预览预算。整合审查与验证见 [审查记录](shelf-memory-review.md)，能力边界见 [实施记录](shelf-memory-implementation.md)。真实远端与多显示器 DPI 仍未验收。

已确认的交互：用户把页签拖入右侧保存区后，收起页签，后台继续运行；再次打开后仍持续保存。仅收纳的任务参与这套自动保存。

## 用户确认的 SSH 范围（2026-10-27 更新）

用户最初暂缓 SSH，之后明确改为：SSH 只在本机保存上下文，重连后能回原工作目录就回；不能可靠回目录时，正常连回并保留上下文即可。不安装或依赖 tmux，不保证远端原进程存活。用户随后明确 **Telnet 不做**，不把这套上下文／目录恢复扩展到 Telnet。不连接未经指定的真实远端，不再追问 tmux 或 SSH 测试会话名。

## 当前实现与使用

- 拖动终端、Claude／Codex、DeepSeek 工作台或普通网页页签到窗口右边缘，立即展开落区后放下；也可点击页签上的收纳按钮。保存成功才收起，失败保留原页签。
- 右侧隐藏时完全不占内容宽度；正常状态只显示离右缘 18px 的 3×36px 灰色细柄，28×72px 透明热区避开滚动条；靠近时细柄轻微拉长、加深，不弹出中间按钮，悬停约 250ms 后直接展开，移到软件主区约 600ms 后收起。拖页签时才临时启用右侧整条落区。把手支持键盘聚焦与点击保持展开，Ctrl+` 切换。自动／悬停／常驻按钮与“任务”标题同排，去掉副标题和底部说明。240～640px 的用户宽度存本机偏好。宽窗口自动停靠，显式收起立即释放宽度，空间不足回退覆盖，不反复挤压工作区。
- 实际宽度达到 360px 时，下层同时排列多个真实小窗口。终端使用同一 xterm／PTY，网页使用原 webview，原位宿主仅改变几何与输入额度，不新建进程、不重放导航、不重复挂载。每窗保留单行标题、状态点与召回操作。网页带地址、后退、前进和刷新／停止工具条；主窗口专用工具在召回后继续使用。
- 展开后顶部按从左到右、从上到下排列约 110～140px 的任务方格，随栏宽每排 2～5 格，末行补低对比度空格；没有任务时保留一行空格。方格内为真实内容缩影、两行任务名及状态。点击仅选中并滚动定位对应的小窗口，下层其他小窗口仍然存在。回到主窗口的任务只保留顶部方格，点击召回同一实例。
- 下层真实终端按小窗尺寸 fit，直接处理选择、滚动、输入法和粘贴；网页使用真实小视口，保留正常页面交互。固定定位源视图显式裁到侧栏滚动区，避免滚动时遮挡格子或标题。收起侧栏后保留最后尺寸并隐藏／inert，避免无意义的大幅 resize。顶部方格仍只读截取缩影，可见时约每 500ms 更新，收窄／关闭／窗口隐藏后停止。
- 方格与小窗口提供执行、空闲、待确认、完成／本轮结束、失败及断线状态点；只复用新鲜官方事件，不从无输出推断空闲，不把回合结束说成整个目标完成。铃铛优先定位有未读提醒的已收纳任务小窗，面板已打开时也直接定位；未匹配的提醒仍保留原详情入口。
- 实际宽度达到 520px 时开放小窗直接输入，窄栏只读；放大按钮可一次达到输入宽度。终端遵守断线、插件归属和 MCP 锁定，网页遵守来源只读限制。键盘只归当前真正聚焦的端面，主终端不同时抢快捷键。悬停或焦点在原生小窗中时保持面板展开。释放回主窗口后移除小窗，仅剩召回方格；不自动回答审批。
- 点击记录回到原实例，记录仍保留；已收纳页签的关闭按钮变为收起，取消保存会先显示运行实例。记录保留工作目录、最近保存时间、状态及本类型的恢复边界，按当前面板宽度展示。普通终端可在详情中显式断开连接。
- 页签关闭与收入任务栏共用 store 的可见内容收敛规则：分屏失去最后一个可见页签时自动合并，隐藏终端与已收纳覆盖层迁入相邻存活分屏并保持身份、连接及收纳标记；单根分屏保留作首页。未激活但未收纳的网页／文档页签仍保护所在分屏。显式断开连接释放资源引用；已保存页签的关闭仅收纳。批量关闭在一次布局事务内完成，重复关闭不再次改变插槽。相关规则由 `pane-store.shelf-lifecycle.test.ts`、`pane-store.empty-target.test.ts`、`PaneView.empty-state.test.tsx` 和 `PaneTabBar.topbar.test.tsx` 自动验证，覆盖混合资源、顺序交换、嵌套分屏、焦点、幂等及恢复出的空分屏关闭入口。
- 收纳任务前台或后台均订阅变化，约 700ms 固定合并窗口顺序落盘；退出时尽力刷盘。主进程把安全引用原子保存到 `config/task-shelf.json`，上限 100 项，无变更不增加 revision。新版本不再自动恢复所有普通网页，浏览设置提供任务区接管说明。
- SSH 收纳后在本机保存最近最多 32768 码元的可读输出和终端明确上报的绝对 POSIX 目录。重连使用原连接引用建立普通 shell，只尝试一次安全引用的 `cd`；目录未知时跳过，目录不存在或远端 shell 不支持时仍保留普通连接。恢复的终端先显示带标记的本机历史，再显示本次连接输出；右侧任务详情也保留只读查看入口，不重放命令。SSH 会话管理器不再启用历史配置中的 tmux 模式，配置界面的 tmux 开关已移除。
- Claude／Codex 持久化已有官方 hooks 提供的精确会话 ID；恢复核对启动器和实际目录／worktree，无 ID 时要求手动选择历史，绝不猜最近对话。
- Harness 捕获可核实的官方当前会话、任务、后台身份与最近状态；同一后台导航须等官方 ack。后台换代或历史定位失效时明确提示手动选择，不重新提交任务或回答审批。

- 已收纳的本地终端只在本次 LyShell 运行期间保留后台现场。退出前 Tasks 一次性原子移入归档，并等待本地终端终止和其他连接断开；宿主即使有收纳标记，在应用连接异常丢失后也按宽限期结束。启动清理旧宿主仍使用当前档案的加密凭据；保存区服务在创建时固定启动快照并原子归档，不自动启动任务。本次新收纳记录不加入旧批次，renderer 重载不重新归档。写入失败保留真实记录与分类并显示 blocked，用户显式重试同一批次；外部变化返回冲突。归档状态不代表进程终止已经得到确认。
- 归档只改变列表分类，后台实例与动态保存继续；归档页提供单个及“全部激活”。点击时固定 ID/revision，分类成功后切 Tasks，只展示方块，显式点击方块后才生成小窗恢复需求；后续滚动不会补发。出队/挂载重新核对当前可视资格。分类不新建 shell、不重放命令、Agent 或 POST。终端及 Harness 由显式点击方块沿原协议在后台恢复到小窗；网页恢复失败与分类失败分别展示。右键菜单保留收纳、归档与取消保存。终端设置可更改展开和收纳快捷键，默认 Ctrl+` / Ctrl+Shift+S，留空禁用；“恢复默认”立即保存 Ctrl+` / Ctrl+Shift+S。

Archive 始终静态，Tasks 可选实时或静态；全部 100 条记录独立于实例/缓存名额，保持可滚动访问。侧栏无保护条件时移出约 600ms 收起，编辑、IME、菜单、键盘导航与拖动受保护；离开整个应用暂停自动收起，固定模式不自动收起，显式关闭不改变模式偏好。普通网页恢复真实并发 1、等待 16、自动驻留 4，超时不提前释放在途许可；主区打开复用实例。预览统一 500ms 时钟、并发 1、队列 16，编码/解码/临时分配分别受预算准入；失效结果在缩放编码前丢弃，来源不旁路持有已淘汰 DataURL。自动深睡与 Rust 继续禁用。
- CLI 在同次应用运行中优先复用原实例；应用退出后原进程结束，记录留在归档。历史会话 ID 继续作为恢复参考，缺少可信 ID 或无法核实期间变化时要求手动选择历史，不自动重发请求或工具操作。

当前不提供通用网页内存／表单快照或手动历史版本。插件所有的终端／网页不纳入保存区，继续服从插件生命周期。

验证详情见 [任务保存区验证记录](task-shelf-verification.md)，历史日志见 `tmp/task-shelf-implementation/verified-report.md` 与 `tmp/task-shelf-continuation/`。下面保留完整设计方向，超出当前实现的条目为后续范围。

## 1. 产品模型

把页签视为任务的显示入口。每个收纳任务有稳定的 taskId，当前页签、运行资源和恢复记录都关联这个 taskId。右侧条目与打开的页签指向同一个任务。

右侧采用完全隐藏与边缘滑出的任务列表，沿用现有主题和项目标识。拖动页签靠近右边缘时展开投放区；窄窗口使用覆盖抽屉。列表以任务名称、资源类型、运行状态为主，最近保存时间按需显示。一张页签对应一个任务，按项目分组；多页签组合任务后续再做。

| 操作 | 行为 |
| --- | --- |
| 拖入未收纳页签 | 建立任务记录并完成首次落盘，再收起显示入口；原进程、连接和网页实例继续存在 |
| 首次保存失败 | 保留原页签与资源，显示失败及重试；不声称已保存 |
| 点击右侧任务 | 找到并显示原实例；实例已不存在时才进入对应恢复流程 |
| 拖回主区或分屏 | 显示或移动原任务视图，右侧条目继续存在并标记“使用中” |
| 再次拖入同一任务 | 收起原视图，更新显示位置；不新增记录或启动第二个进程 |
| 点击已收纳页签的关闭按钮 | 默认收起回保存区；提示本次为收起，终止操作单独提供 |
| 从保存区移除 | 停止后续自动保存并删除该任务恢复记录；运行中的视图回主区，不隐式终止任务 |
| 终止任务 | 按真实后端协议停止，确认终态后显示“已停止”；保留恢复记录与历史摘要 |
| 归档任务 | 从活跃列表移出；仍运行时先明确选择收纳继续或终止，归档本身不等同暂停 |

提供右键“收纳到任务区”和键盘入口，与拖放完全同义。显示“运行中／待审批／已完成／连接断开”等真实状态，不能以隐藏、失焦或静默输出推断完成。审批继续交给现有审批界面处理，不因任务收起而批准。

### 右侧展开与带鱼屏适配

普通窗口默认完全隐藏，内容预留宽度为 0；右侧细柄距右缘 18px，不参与布局，悬停约 250ms 后以 480ms 动画直接滑出覆盖面板（收起 440ms），移到软件主区约 600ms 后收起，鼠标或键盘焦点仍在面板内时保持展开。鼠标移出整个软件窗口或切换软件时暂停自动收起，返回侧栏继续保持，返回主区后重新等待 600ms；Esc、收起按钮和快捷键仍可主动收起。减少动态效果模式下直接切换。键盘聚焦细柄只显示焦点环，Enter／Space 打开后移焦面板，收起时将内部焦点还给入口。点击把手可保持展开，Esc 退出临时展开；拖动页签靠近右边缘立即展开投放区。隐藏面板不可聚焦、点击或被辅助技术导航，透明边缘和快捷键保留可访问入口。未达到预览宽度时不改变来源尺寸；真实小窗口沿用最后尺寸，避免仅开合面板就来回 resize。点击任务方格切换小窗与仅方块保活状态，主区显示的任务也由方格收回，侧栏保持展开。

带鱼屏使用实际窗口的 CSS 可用尺寸、左侧栏占用与工作区剩余宽度判断，而非物理分辨率或显示器型号。以下为待真实界面验证的初始阈值：

| 窗口条件 | 自动模式下的右侧任务区 |
| --- | --- |
| 窗口宽度不足约 1800px，或停靠后主工作区不足约 1100px | 完全隐藏与边缘覆盖展开；半屏／分屏使用时回到此模式 |
| 窗口宽度至少约 1800px，且主工作区足够宽 | 停靠展开约 280～320px，工作区一次性让出空间，列表与运行状态常显 |
| 窗口宽度至少约 2400px，且主工作区足够宽 | 停靠区可调至约 320～400px，随栏宽开放真实小窗口，未在侧栏中的任务仍只显示召回卡片 |

设置提供“自动／悬停展开／固定展开”，显式偏好优先；记住用户调整的面板宽度。窗口空间不足时临时回退覆盖模式，保留偏好，恢复宽度后再应用。自动模式在阈值附近使用约 80px 的回差并等待窗口调整稳定，避免反复展开收起。

常驻模式只在 36px 首行下方占内容空间，首行页签仍可延伸到窗口右边缘，窗口控制按钮的留白保持原位。内容树保留停靠宽度，首行最右叶子的页签条补回同一宽度；只沿该叶子的分屏祖先放开首行延伸，终端和网页内容层继续裁切，切换停靠不重挂运行实例。

超宽窗口允许用户把任务从右侧拖入指定分屏或拆出新分屏，在足够空间下形成“终端／AI／网页”并排工作。不会因识别到带鱼屏而自动创建分屏、启动任务或改变保存范围。任务始终只有一个身份，拖到不同区域仅改变视图位置。

考虑超宽屏右侧距离较远，任务区支持可配置快捷键与主区右键“收纳”，拖动过程中提供可见落区；拖入后不要求再移动到角落确认。展开、收起和预览不抢当前输入焦点。正式实施需在宽窗口、相同屏幕半屏窗口、高 DPI 缩放与多显示器移动场景中检查布局和焦点行为。

## 2. 动态保存

收纳后的任务始终订阅自己的状态变化，无论视图位于主区还是右侧。前台与后台只影响显示，不改变是否持续保存。

- **运行实例**：保持当前 PTY、远端会话、Harness 后端或网页实例。收起不能走现有关闭／断开／销毁管线。
- **恢复记录**：保存连接配置引用、项目与 worktree 身份、精确会话引用、页面入口、视图位置等类型允许的字段。只保存本类型真正支持恢复的内容。
- **进度展示**：保存可信状态、最近活动、有限输出摘要或可选终端预览。预览与运行进程分开标记，不把旧画面当成已续接的现场。

建议普通元数据变更合并约 0.5～1 秒写入，持续变化时最多约 5 秒落盘一次；首次收纳、精确会话 ID 变化、任务终态等关键事件立即提交。数字为初始性能参数，需压测后调整。正常退出限时刷盘；崩溃只能保证已经提交的记录。

主进程负责持久化和顺序：每任务递增 revision、串行提交、原子替换，忽略晚到的旧 revision。首次收纳时先订阅再读取快照，用事件序号衔接，避免快照期间丢失新状态。磁盘失败继续保留现场与待写更新，标记“尚未保存”，不能删除上次有效记录。

终端输出采用有上限的内存环形缓冲；若启用本地历史则按块追加和轮转，避免每个字符重写完整屏幕。持久化输出需明确内容策略，不默认记录键盘输入或任意 shell 历史。周期保存不生成一排重复任务；手动保存版本可作为后续独立功能。

## 3. 各类型的恢复能力

### SSH 远程终端

只保存本地上下文与恢复引用，不托管远端进程。记录原保存连接的 ID、目标指纹、可信目录报告与有界输出尾部。密码、私钥等连接配置凭据不复制到任务记录；输出内容仅来自已显示的终端数据，不记录原始键盘输入。

目录只认 OSC 7／9;9 的显式报告，不从提示符或 `cd` 回显猜测。没有 shell integration 的服务器可能无法报告目录，此时直接重连到默认目录；这是支持的降级结果。目录信息不能当作已确认恢复成功：只有后续目录报告才能说明实际位置。

历史输出作为本机参考文本展示，去除旧控制序列、限制长度。恢复时在连接产生新输出前，把历史一次性放入本机终端显示流与订阅初始缓冲，标明历史和本次连接的分界，兼容终端先建立或连接先完成的顺序；已运行实例反复打开不重复注入。历史显示不经过远端输入接口，不重新执行旧命令或旧控制序列。已收纳 SSH 的内存尾部在断线清理后仍保留，以便最终快照；连续输出合并约 3 秒再保存，目录或状态变化可提前刷新。归档不停止保存，取消保存才释放这份上下文缓冲。

重连时核对原连接目标指纹，连接配置已换主机／用户时拒绝误接。使用新的交互 shell，不重放旧业务启动命令；只在目录有效时发送一次经过 POSIX 单引号引用的 `cd`。旧记录中的 tmux 名不再用于创建或附着远端会话。没有已保存连接引用的任务仍可保留上下文，但跨应用退出后需要手动选择连接。

Telnet、串口、网络设备 CLI 或不支持 tmux 的主机，只能保证当前连接后台使用及已支持的连接信息恢复；不承诺原交互进程续接。

### 本地终端、Claude 与 Codex CLI

应用仍在运行时复用原 PTY，保持正在进行的任务、输入现场和待处理提示。视图收起不发送中断或退出指令。

本地终端现由独立宿主持有（系统加密存储不可用时仍为原有普通 PTY，并清楚标记恢复边界）。宿主只监听随机本机管道，凭据仅存系统加密密文。收纳保留须收到宿主确认后才写入任务记录；未收纳的宿主失去客户端后约 5 秒清理，收纳的宿主持续运行。恢复不重放输入或启动命令，终止须有实际退出证据。本地机器重启后不能恢复原进程。

CLI 的对话恢复记录应包含提供方、精确 session／thread ID、实际 cwd、项目／worktree 身份、启动配置引用及配置版本。会话 ID 必须来自可信的官方结构化事件或受支持的集成，不能靠终端显示文字、目录最近修改时间或“上次会话”猜测。

恢复优先顺序：原 PTY 仍在则直接显示；进程已退出但有可靠会话 ID，则显式调用该 CLI 经本机版本确认的精确续接入口；没有 ID 时标记“需手动选择历史”。恢复历史不会自动重发上次请求，也不意味着上次正在执行的工具可接着跑。

当前项目现场只提供 Codex／Claude 历史选择器，没有持久绑定精确会话 ID；本提案不能把该入口称为已经实现准确续接。现有 `TuiActivityRegistry` 已通过启动器注入的官方 hooks 接收 `cliSessionId`，但仅在内存保留，可优先复用其身份校验与事件订阅。收纳时应捕获已有可信 ID，之后跟随会话切换更新；手动启动、hook 未接入或尚未收到事件时，仍标记尚无精确 ID。后续实施前重新核实所装 CLI 的接口并做真实验证。

### DeepSeek Harness

持久记录官方历史会话引用、工作目录、工作台入口类型，以及最近已知任务摘要；运行期另跟踪后端 identity、sessionId、taskId、归属和审批状态。

同一后台与有效原归属内，以精确 ID 重新读取状态，打开视图不能创建新任务。后台换代或 LyShell 重启后，现有原生协议不恢复控制权，旧 taskId 和审批 ID 不能用于新实例。界面标记“历史可查看／控制权需重新建立”，仅通过后续受支持的归属与续接协议恢复操作；不擅自接管官方、PetLink 或其他凭据的会话。

DeepSeek 官方网页当前是单例工作台。多个收纳任务可以引用不同历史会话，但不应假定已有多个可独立保活的工作台实例；要可靠定位具体历史，需要受支持的导航／历史接口，不能保存含凭据的运行期后台 URL。

### 普通网页

应用运行期间保留原 webview，收起时隐藏视图，重新打开保持同一实例；复用现有常驻 WebTabLayer，增加收纳位置和挂载生命周期。后台网页仍可能受到 Chromium 调度、站点逻辑、网络和系统休眠影响，不能承诺所有网页脚本持续全速执行。

跨重启保存类型允许的入口 URL、标题、浏览 partition 引用及可恢复的滚动位置。登录态继续由 Chromium 浏览数据管理，不复制 cookie 或密码进入任务记录。页面内存、任意表单和 JS 执行现场不能通用恢复；站点支持草稿时优先使用站点能力。POST 不重放，一次性认证入口不持久化，受保护 URL 明确标记只能保留当前现场。

旧“恢复网页标签”设置目前会自动保存普通网页地址。要满足“只有拖入才保存”的严格规则，应将页签自动恢复来源统一到任务保存区，提供一次明确的设置迁移；浏览器历史、书签和登录数据仍按各自设置管理。旧项目现场的手动快照可保留，但不能成为所有临时页签自动入库的后门。

拖动尺寸（2026-10-29）：按帧合并指针位移，直接更新面板尺寸和主区 CSS 留白，原生端面同帧测位；逐帧不更新 React 与全局留白状态，避免主窗口重渲染阻塞边界跟手。拖动期间保持方块列数／横栏行数及小窗显隐，原小窗连续缩放，不跨 360px 临界点反复拆装。停靠模式等拖动结束后再评估。松手、取消或丢失捕获均提交最后尺寸并移除临时 CSS 留白，只持久化落定结果；最后换列提供 180ms 位置／缩放衔接，遵守减少动态效果偏好。竖栏不监听正文尺寸回写状态，横栏拖高直接计算当前正文预算。

拖宽性能补充：原生端面外层继续按帧移动、裁剪，但终端网格 fit 和网页 guest 视口重排推迟到手势结束，避免多分屏和长终端输出阻塞边界跟手。全局手势采用独立租约，最后一个手势结束后恢复适配；释放、取消、捕获丢失、失焦及卸载都回收租约。网页恢复原尺寸样式，不重挂、导航或重载；终端只同步最终网格尺寸。

## 4. 实现分层

- **TaskShelfRecord**：稳定任务身份、类型、标题、项目归属、排序、revision、恢复能力、类型专用恢复引用与最近保存结果。运行中、连接中、显示位置、是否已保存是不同维度，分别表达。
- **运行资源注册表**：维护 taskId 到终端 runtimeId、webview 实例或 Harness 实例身份的映射。资源所有权不依赖页签组件是否挂载。
- **类型适配器**：分别实现捕获、观察、显示、收起、探测恢复、显式续接、停止和释放；每个适配器声明实际恢复能力，避免一个通用 restore 假装恢复一切。
- **页签／保存区视图**：只负责显示位置、拖放、键盘和焦点；不自行启动或终止后端任务。
- **主进程存储与恢复协调器**：校验 IPC 白名单和身份、顺序落盘、处理未知回执与恢复去重。精确会话标识与运行期凭据分离，任务记录只引用现有受保护凭据库。

开机只加载保存区清单，并按需探测真实资源。用户点击后才执行会启动本地进程、SSH 认证或 CLI 的恢复；不在启动时把所有条目一齐重启。点击恢复须有在途锁，超时先核实资源状态，不能重复启动。已完成任务保留为“已完成”，不显示为仍在后台执行。

## 5. 落地顺序和验收

1. **统一收纳与动态保存**：终端、网页、Harness 视图可收起再打开，复用原资源；只有收纳项写入清单；原子保存和错误状态完整。
2. **SSH 本地上下文与普通重连**：输出与已知目录在本机持久化，重连尽力回目录，失败保留普通连接与历史；不恢复远端原进程，不扩展到 Telnet。
3. **CLI 精确续接**：实现可靠 ID 捕获与版本适配，用两个同项目会话及两个 worktree 验证不会串会话。
4. **Harness 与退出后的保活**：依官方协议支持历史定位和归属恢复；本地终端常驻服务作为独立能力建设，明确其适用系统与退出规则。

基础验收必须覆盖：收纳后程序仍运行；反复展开／收起无重复实例；前台继续使用仍保存最新状态；未收纳项不自动恢复；保存失败不丢原页签；连续变化后退出／重启；后端换代不误接；CLI 缺 ID 不猜测；重复恢复无重复任务；审批不自动答复；网页不会重放 POST；真实终止后的状态与资源一致。截图与交互检查由 Codex 完成。

恢复补充：显式移回 Tasks 会恢复可用实例并收纳到任务区。已确认结束的本地宿主会在保存目录新建普通 shell（包括原 Agent 终端），不重放启动命令或旧请求；探测结果未知时保留错误，避免重复启动。恢复失败记录保留在归档，重试入口重新执行恢复。

任务区页签行右侧：Tasks 显示全部收回按钮，一键收回主区中全部已收纳任务，保留原实例及未收纳页签，Archive 显示全部移回任务区，Alerts 不显示任务操作。按钮不属于 tablist，方向键只在三个页签间移动。窄于 420px 时操作保留图标和完整悬停提示，避免挤压页签；点击任务方格不会主动收起侧栏。

任务栏附着位置：展开后的标题行可拖到内容区四边，靠近目标边缘才吸附；中央松手、Esc 或取消保留原位置。收起细线仅用于展开，不支持拖动或方向键换边。本机记住边缘、宽度与高度。上下附着时左侧 124×124 正方形任务卡按可用高度从上到下填满每列，再从左到右新增列，右侧终端或网页窗口从左到右排列，标题及操作位于小窗上方，窗口主体固定 16:9（包含网页地址栏），浏览器与终端等宽等高；横版按可用高度联动计算窗口宽度，上限为方块区右侧的可用宽度，分别纵向/横向滚动。左右附着沿用竖向面板。停靠留白跟随边缘，首行页签与系统控制继续留在窗口顶端；空间不足回退覆盖。

横向任务栏会测量正文实际宽高（扣除标题、页签及错误提示），重算方块行列。正文空间不足以完整放下顶部标题及 16:9 窗口主体时，不挂载小窗口，仅展示方块；方块使用整栏宽度，继续按列向右扩展。调高后复用原运行实例恢复小窗口，不重放命令。

展开细线四个方向均距内容边缘 6px，热区保留。仅展开后的标题行可拖动换边，横版支持工具栏空白区域；按钮、页签与模式选择不触发拖动。拖动后保留原展开状态，中央松手、Esc 或取消保留原位置。吸附提示为贴边细长区域，当前目标用琥珀色高亮。横版顶部合并为约 45px 单行工具栏：页签、显示模式、批量操作和收起；宽度不足时模式改用下拉框，保留辅助技术名称。


任务区内容优先布局：竖向顶部收为约 80px 的标题与页签两行，横向维持约 44px 工具栏。显示模式与实时显示合并到标题旁的显示设置入口，按需展开设置区；Esc 先关闭设置区并归还焦点。任务收回及归档全部激活位于页签行右侧。成功结果只保留标题旁的完成标记，完整计数可悬停或通过辅助技术读取；失败、冲突与缺失结果继续在内容前显式提示，失败可重试。下方任务与小窗口采用连续白色背景、较轻边线和统一留白，保留两行任务名与状态。标题拖动换边、细线仅展开及四边 6px 边距继续保留。


Tasks 方块负责保活，激活后默认只展示方块。仅方块状态下单击打开小窗口，使用小窗口的放大按钮进入主工作区；小窗或主区正在显示时，再点同一方块即收回到仅方块保活，再点才重新打开小窗。收回不关闭 PTY、断开连接或重建网页实例。窄栏自动扩到预览宽度，横版为显式打开的小窗保留空间。无绑定记录仅在点击后后台恢复，终端不先经过主区；普通网页沿用 explicitShelf 需求及可见性校验。任务详情移入右键菜单，不再默认展示额外终端标题行或打开按钮。


小窗终端首帧：后台恢复期间，连接状态先更新会话状态，自动主区落位等待恢复绑定及隐藏落位完成，避免 connected 早于 restore 回执时先显示到主区。有效小窗矩形就绪前，宿主保持透明、裁空与 inert；普通连接自动打开、克隆手动落位及显式放大继续沿用。回归覆盖早到通知、新旧会话、普通连接并行、失败释放与迟到关闭。
